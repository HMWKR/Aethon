이미지 교체를 시작하기 전에 안내서 `design/plan-image`를 아직 읽지 않았으면 읽고 "이미지 교체"를 따른다.

## 골격의 hints와 slotHints 읽기

`prepare_design_plan` 응답의 `hints`는 현재 골격의 요약과 구조 결정 지점이고, `slotHints`는 슬롯별 지침이다.
`plan`을 채우기 전에 둘을 먼저 읽는다.

`slotHints`에 영어 작성 안내가 있으면 작성할 내용의 의미를 유지하면서 해당 텍스트박스 전체를 영어로 작성한다.
같은 문구를 복사하는 반복 라벨과 그림자 제목도 같은 언어로 작성한다.
이 안내는 장식 런의 원고 영문 표현 조건보다 우선한다. 글자 수, 런 연결, 숫자와 `keep` 규칙은 유지한다.
그 밖의 박스는 확정한 디자인 언어와 기존 슬롯별 작성 규칙을 따른다. 이 안내는 글꼴을 바꾸라는 뜻이 아니다.

- `hints`의 첫 줄은 프리필한 슬롯 수와 페이지별 분포다. 그 뒤에 `[note]`가 있으면 슬롯 분포를 검토하라는
  안내다. 슬롯 수만으로 페이지 축소 여부를 결정하지 않는다. 원고의 필수 내용과 수치·조건을 배치할 수
  있는지 확인한다. 불필요한 페이지나 반복 항목만 제거하고 실제 슬롯 용량을 확인한다.
- `replacements`는 페이지 키(`"2"`, 복제 페이지는 `"2#2"`) 아래 노드 키(`"n8"`)에 문자열 또는 런
  배열이 든 모양이다. 배열의 i번째가 런 i이고 `null`은 건너뛴 런이다. `slotHints`와 finding의 슬롯 id
  `2n8:1`은 `"2"` → `"n8"` → 배열 1번째를 가리킨다. 슬롯 id 키 `"2n8:1"`도 받지만 골격의 모양을 바꾸지
  않는 것이 가장 안전하다.
- `hints`에는 미리 채운 `keep`, `display_copy`, 페이지 삭제와 `coverage`의 현황, `at`에 쓸 페이지 라벨이 있다.
  구분자만 있는 슬롯은 `keep`에 이미 들어 있다. 필드별 작성 규칙은 아래 해당 절을 따른다.
- "구조 결정 지점" 아래 `page N:`은 그룹 칸 수, 표의 행·열, 차트 타입·카테고리와 변경 가능 여부다.
  콘텐츠 개수에 맞춰 `set_group_count`·`table_add_row`를 정하고, 차트는 안내서 `design/plan-data`의 "차트 작성 규칙"을 따른다.
- `slotHints`의 "표 … 헤더/N행 … 짝(행 라벨)"은 그 슬롯이 어느 행에 속하고 어느 라벨과 짝인지를,
  "그룹 … 아이템 k/n"은 같은 카드에 속한 슬롯임을 뜻한다. `replacements`는 표의 행과 카드 단위로
  정렬되어 있으므로 이웃 슬롯이 같은 행이나 카드다. "숫자 자리"는 숫자만 넣고 설명은 옆 라벨로
  보내라는 뜻이고, "런"은 같은 줄로 이어 붙는 조각이라 경계 공백을 유지하되 조사는 앞 런에 붙여 쓰라는 뜻이다. "표시용 큰
  글씨"는 짧게 쓰라는 뜻이고, "상자 한글 약 N자 추정"은 그 텍스트 상자 전체의 추정 용량이다. "공유 용량"이
  붙은 슬롯은 같은 상자의 런들이 한 예산을 나눠 쓰므로 런마다 N자를 넣지 않고 합계를 N자 안에 맞춘다.

## replacements 작성 규칙

- 골격의 모양(페이지 → 노드 → 런 배열)과 값의 자리를 그대로 두고 값만 바꾼다. 배열의 길이와 `null`
  자리를 바꾸지 않는다. 런을 비우려면 값을 빈 문자열로 두지 말고 그 런의 내용을 옆 런에 이어 쓴다.
- `chars`를 대략적인 상한으로 사용한다. 자동 글자 축소는 작은 오차를 흡수하는 기능이지 긴 문장을
  작은 글자로 넣는 수단이 아니다. `fontSize`는 plan에서 지정하지 않는다.
- `fontSize` 40 이상의 표시용 슬롯(제목, 큰 숫자)이 25% 넘게 줄어야 들어가는 텍스트는 `fit_small`
  warning이 된다. 텍스트를 짧게 쓰거나 단위와 수식어를 옆 라벨 슬롯으로 옮긴다. 페이지에서 가장 큰 글자(페이지 제목)가
  그만큼 줄면 `title_small` error로 저장이 보류된다. 서버는 원문에 딱 맞던 한 줄 제목 상자를 빈 쪽으로 먼저 넓히므로,
  그래도 줄어드는 제목은 짧게 쓴다.
- 제목이 "N가지", "N단계"처럼 개수를 말하면 카드 수를 `set_group_count`로 N에 맞춘다. 3칸 그룹에 "4가지"를 넣지 않는다.
- 목차 페이지를 쓰면 항목 순서와 이름을 최종 페이지 순서와 제목에 맞춘다.
- 여러 줄 본문은 원본보다 2줄 이상 늘면 `grow`, 마지막 줄에 한두 글자만 남으면 `orphan` warning이
  된다. `grow`는 "공간이 부족할 때 plan 수정"을 따르고, `orphan`은 문구 또는 줄바꿈을 조정한 뒤 전체 높이를 다시 확인한다.
- 표 칸(`tableCell`이 있는 슬롯)은 원문 줄 수 안에서 쓴다. 칸 글이 행보다 길어지면 서버가 행을 늘리고, 표 아래 요소까지
  여유가 없으면 표 글자 전체를 줄이며, 그래도 안 들어가는 칸은 `table_cell_overflow` warning이 된다. 한 칸만 길면 그 행 전체가
  높아지고 표 글자가 다 같이 작아지므로, 같은 행의 다른 칸과 분량을 비슷하게 맞춘다.
- 줄마다 표식이 붙은 목록 본문(`lineMarkers`)의 줄 수가 표식보다 많으면 `list_overflow` warning이 된다.
  표식마다 문장 하나가 한 줄에 들어가도록 문장을 짧게 쓰거나 문장 수를 줄인다. 표식을 지우는 것은 해결이 아니다.
- 줄이 늘어난 텍스트가 아래나 옆의 글·아이콘·이미지를 새로 가리거나 카드 밖으로 나가면 `grow_overlap`
  warning이 된다. 그룹 안 요소도 검사한다. 서버는 주변 요소를 옮기거나 지우지 않으므로 텍스트를 줄이는
  것이 먼저이고, 제목·부제·아이콘처럼 한 묶음이 분명할 때만 `move_nodes`로 함께 옮긴다. 가린 요소를 지우는
  것은 해결이 아니다.
- 반복 그룹에서 같은 역할의 슬롯은 분량을 서로 비슷하게 맞춘다. 서버가 그룹의 글자 크기를 통일하므로
  하나만 길면 그 슬롯만 작아지고 `role` warning이 남는다.
- 같은 페이지의 서로 다른 슬롯에 같은 문구를 넣지 않는다(`dup` warning, 한 페이지에 3쌍 이상이면 `dup_heavy` error).
  제목과 표 헤더에 같은 말을 반복하거나, 첫 카드의 제목 슬롯에 페이지 제목을 넣고 뒤에 나오는 진짜 제목 슬롯에 같은
  문구를 다시 넣는 실수가 전형적이다. 골격의 "페이지 제목", "부제" slotHint를 따른다.
  예외는 그림자 제목이다. 원본에서 같은 문구가 겹쳐 놓인 슬롯 쌍(표지의 겹친 제목, 외곽선 제목)에는 같은 문구를 넣는다.
  서버가 가장 잘 보이는 노드 기준으로 문구·글자 크기·줄바꿈을 맞추므로 다른 문구를 넣으면 `shadow_text` warning과 함께 덮어쓴다.
- 수치 문구에는 사용자가 제공한 값을 정확하게 쓴다. `2,800`을 `2.8K`로 바꾸지 않는다.
- 남길 페이지의 템플릿 원문을 모두 교체한다. 의도적으로 유지할 짧은 문구만 `keep`에 넣는다.
  템플릿 값을 그대로 복사해 `replacements`에 넣는 것은 교체가 아니며, 교체하지 않은 것과 같이
  빈값으로 처리된다.
- 차트와 표의 수치는 비워 둘 수 없다. 건드리지 않으면 템플릿 예시 수치가 가짜 숫자로 남는다. 수치가
  없으면 사용자에게 확인을 받거나 그 페이지를 쓰지 않고 해당 항목을 `coverage`에 `drop`으로 적는다.
  차트를 0이나 임의 값으로 채우지 않는다. 필요한 텍스트는 콘텐츠로 채우고, 불필요한 텍스트는 관련 요소나 페이지를 삭제한다.
  원래 내용이 있는 슬롯을 빈 문자열로 보내면 `expose` error가 되며, `notes`에 이유를 적어도 해소되지 않는다.
- 날짜와 현재 연도를 추측하지 않는다. 필요한 날짜가 없으면 질문하거나 관련 요소를 지운다.
- 텍스트 중간의 `\n`은 실제 줄바꿈이므로 꼭 필요할 때만 사용한다. `\n` 바로 뒤를 구두점으로
  시작하지 않고 구분자는 앞 줄 끝에 붙인다. 서버가 교체한 한글 본문의 줄바꿈을 어절 단위로 바꾸므로
  (`word_break` info), 어절이 중간에서 끊기는 것을 막으려고 `\n`을 넣지 않는다. 상자가 좁아 양쪽 정렬을
  지킬 수 없는 본문은 서버가 왼쪽 정렬로 바꾼다(`justify_left` info). 한 줄 높이의 제목
  슬롯에 넣은 `\n`은 아래에 자리가 없으면 서버가 공백으로 바꾸므로 두 줄이 되지 않는다. `1단계 호기심`을
  `1\n단계 호기심`이나 `1단계 호\n기심`으로 쓰면 `1 단계 호기심`, `1단계 호 기심`이 된다.
- 텍스트 뒤의 강조 막대나 밑줄 도형은 문구 길이에 맞춰 자동으로 늘어나거나 줄어들지 않는다.
  기존 도형 길이에 맞는 문구를 사용하거나, 문구와 어긋나면 해당 도형을 `delete_nodes`로 지운다.

## display_copy 작성 규칙

manifest에 `displayGroups`가 있는 페이지를 쓰면 그룹마다 `display_copy` 항목 하나를 작성한다.
`prepare_design_plan`은 이 항목을 템플릿 원문 `lines`와 빈 `semantic_slots`로 프리필하므로, 값을
바꾸지 않으면 미교체로 빈값 처리된다.

```json
{"display_copy":[{"group":"0d1","lines":["SMART","EASY"],"semantic_slots":["0n26:0"]}]}
```

- `group`은 `displayGroups[].id`다. 같은 그룹을 두 항목에 쓰지 않는다.
- `lines`의 개수는 그룹 `lines`의 개수와 같고, 각 문자열의 글자 수는 해당 줄의 `chars`와 정확히 같아야
  한다. 서버는 번역하지 않고 글자를 상자에 배분만 하므로, 글자 수에 맞는 영문 카피를 고르는 일은
  모델의 소관이다.
- 영문 조형만 허용한다. 한글이나 한자를 넣으면 `display` error가 된다.
- 원고에 한글이 있으면 같은 의미를 한글로 남긴 `replacements` 슬롯(부제, 본문 제목 등)을
  `semantic_slots`에 적는다. 영문 카피만 남기면 원고의 의미가 사라지기 때문이다.
- `display_copy`가 소유한 슬롯을 `replacements`에 중복 기재하지 않는다.

## 템플릿 원문 유지하기

브랜드명, 짧은 섹션 라벨처럼 최종 디자인에 의도적으로 남길 템플릿 원문만 `keep`에 슬롯 또는
노드 식별자로 지정한다.

```json
{"keep":["0n1:0","2n4"]}
```

- 16자 이하의 짧은 문구에만 사용한다.
- `하세요`, `합니다`, `OO`, `XX`, `00`, 대괄호가 포함된 안내 문구나 자리표시 문구에는 사용하지
  않는다. 서버가 거부하고 빈값으로 처리한 뒤 `keep` error로 알린다.
- 숫자가 든 텍스트는 `01`, `Q1`, `Part 1`, `STEP 01.` 같은 순번 표식만 `keep`할 수 있다. `78.0`,
  `24,000`, `42.5억`, `+20.4%`, `2080` 같은 템플릿 예시 수치는 거부된다. 숫자가 없는 단위 라벨(`억`,
  `%`, `명`)은 `keep`할 수 있다.
- `keep`은 빈칸 경고를 피하는 수단이 아니라 의도를 선언하는 수단이다. 한 페이지에서 살아남은 텍스트가
  4개 이상이고 그중 과반이 `keep`이면 그 페이지는 사실상 템플릿 원본이므로 `keep_heavy` error가 된다.
  채울 내용이 없는 페이지는 `delete`한다.
- 원문을 교체하기 번거롭다는 이유로 페이지 전체나 여러 노드를 `keep`에 넣지 않는다.
- 복제본의 원문을 유지하려면 `0n1:0#2`처럼 복제 접미사를 붙인다.

## 원고 누락 확인하기

`coverage`에는 사용자가 제공했거나 모델이 작성한 콘텐츠의 의미 단위를 모두 나열한다. 각 항목에는
`src`와 함께 최종 페이지 라벨인 `at` 또는 제외 이유인 `drop` 중 하나만 넣는다. 이 목록은 템플릿의
원문이 모두 처리되었는지가 아니라 사용자 콘텐츠가 조용히 누락되지 않았는지를 확인한다.

```json
{
  "coverage": [
    {"src":"서비스 개요","at":"1"},
    {"src":"가격 정보","drop":"사용자가 가격 수치를 제공하지 않아 임의로 작성할 수 없어서 제외함"}
  ]
}
```

- `at`은 모든 `page_ops`를 적용한 뒤의 최종 페이지 라벨을 사용한다. 라벨은 원본 템플릿 페이지 번호이고,
  복제되어 같은 원본 번호를 사용하는 페이지는 `2#2`, `2#3`처럼 표시한다. 최종 순서 번호(1, 2, 3 …)가
  아니다. 순서 번호가 우연히 라벨 범위 안이면 오류 없이 엉뚱한 페이지에 붙으므로 `prepare_design_plan`의
  `hints`가 나열한 라벨을 그대로 쓴다.
- `drop`은 무엇을 왜 담지 못했는지 사용자가 이해할 수 있도록 12자 이상으로 구체적으로 작성한다.
- `drop`은 누락을 신고하는 것이지 항목을 제거할 권한이 아니다. 목적이나 레이아웃이 부족하다는 이유만으로
  항목을 `drop`하지 않는다. 먼저 `duplicate`, `set_group_count`, `place_block`이나 같은 템플릿의 다른 페이지로
  담을 자리를 검토하고, 그래도 담지 못하면 사용자에게 알린다.
- 뺀 항목이 전체의 30%를 넘으면 템플릿이 콘텐츠에 맞지 않는다는 신호다(`drop` warning). 신고를
  생략하지 않고 안내서 `design/plan-structure`의 "콘텐츠 중심 재구성"에 따라 담을 자리를 다시 찾는다.
- 원고 의미 단위를 합치거나 요약했더라도 원래 항목을 각각 `coverage`에 남겨 누락 여부를 확인한다.

### sources와 coverage 대조

`sources`는 원고 항목 이름 목록이다. 형식과 거절 조건은 `prepare_design_plan`의 `sources` 설명에 있다.
"3 오픈 체크리스트"처럼 번호 뒤에 내용을 붙인다. `sources`가 있으면 `coverage`는 필수이고,
`replacements`가 없어도 서버가 두 목록을 대조한다.

- `coverage`의 `src`가 항목명과 같거나, 항목명으로 시작하고 바로 뒤가 글자나 숫자가 아니면 그 항목의
  신고로 인정한다. 세분화는 허용되므로 "시장 규모 (국내)"는 "시장 규모"의 신고다. "전략로드맵"은
  "전략"의 신고가 아니다.
- 대응은 1:1이다. `src` 하나가 여러 항목을 겸하거나 항목을 한 줄로 이어 붙이면 나머지 항목은
  누락이다. 같은 이름의 항목이 둘이면 신고도 둘이어야 한다.
- 신고되지 않은 항목은 `coverage` error가 되고, `force`로 우회할 수 없다.
- 형식이 잘못되면(문자열 배열이 아님, 빈 배열, 빈 문자열 원소) `plan`이 `path` `/sources`로 거절된다.

## 복제된 텍스트 지정하기

`duplicate`, `set_group_count`(늘릴 때), `duplicate_nodes`, `copy_nodes`, `place_block`, `table_add_row`로
생긴 텍스트는 원본 슬롯 식별자에 `#2`, `#3`을 붙여 `replacements`에서 지정한다. 같은 원본을 두 번
복제했다면 두 번째 복제본은 `#3`이다.

```json
{
  "replacements": {
    "4#2": { "n2": "복제한 페이지 제목" },
    "7": { "n8": "원본 행의 첫 번째 값" },
    "7n8#2": "새 표 행의 첫 번째 값"
  }
}
```

복제한 페이지는 페이지 키에 `#2`를 붙인다(`"4#2"`). 같은 페이지 안에서 노드만 복제된 경우는 노드 키에
붙이며, 페이지 객체 안(`"7": {"n8#2": "…"}`)과 최상위(`"7n8#2"`) 어느 쪽에 써도 같은 슬롯 `7n8:0#2`다.
페이지 키와 노드 키 양쪽에 붙이면 `unresolved`로 거절된다. 골격에는 복제본이 없으므로 직접 더한다.

페이지가 늘거나 줄어도 노드 식별자의 페이지 번호는 원본 manifest를 기준으로 한다. 복제된
페이지의 슬롯을 다음 원본 페이지의 식별자로 잘못 가리키지 않는다.

## 색 바꾸기

사용자가 특정 색을 지정하지 않았더라도 브랜드 정보, 원하는 분위기와 디자인 목적을 근거로
`recolor`를 사용할 수 있다. 변경할 근거가 없다면 임의의 색을 선택하지 않고 템플릿 색상을 유지한다.

```json
{"recolor":{"map":{"#c8a67e":"#5b86b8"},"exact":["#f6f6f6"]}}
{"recolor":{"hue":120,"chroma":0.8}}
```

- 기본 색상 매핑은 원본 밝기를 유지한다. 같은 색이 글자와 배경 양쪽에서 쓰일 수 있기 때문이다.
- 밝기까지 정확히 바꿔야 하는 색만 `exact`에 넣는다. 글자와 배경의 대비가 유지되는지 판단한다.
- `neutral: true`인 색은 `hue`로 바뀌지 않으므로 필요하면 `map`을 사용한다.
- `palette`에 없는 색을 매핑하지 않는다.
- `hue`를 적용하면서 로고색이나 브랜드 색을 유지해야 하면, 해당 색을 `map`에서 원래 색과 같은
  값으로 매핑하여 일괄 색상 변경에서 제외한다.
- 사진 색은 바뀌지 않고, 잠긴 일러스트 색도 남을 수 있다. 변화가 불완전하면 `notes`에 기록한다.
- 표의 일부 칸만 칠하는 것은 `recolor`가 아니라 안내서 `design/plan-data`의 "표 칸 색 지정하기"를 따른다.

## 공간이 부족할 때 plan 수정

첫 배치부터 각 문구를 넣을 상자의 `chars`와 `slotHints`를 확인한다. 같은 상자의 모든 런이 용량을
공유한다. `chars`는 현재 표시 크기의 추정치이며 줄바꿈·글자 폭·주변 요소에 따라 달라지므로 실제
적용 결과를 대신하지 않는다. 의미 단위 개수만으로 페이지를 늘리거나 한 장에 들어간다고 판단하지 않는다.

용량을 넘는 문구가 있거나 `fit_floor`, `fit_small`, `grow`, `grow_overlap`, `table_cell_overflow` 또는 텍스트 겹침·잘림이 확인되면 다음 순서로
plan을 수정한다. `squeeze`는 이 검토를 시작하는 신호이며 그 자체가 공간 초과 판정은 아니다.

1. 중복 표현과 불필요한 수식어를 줄여 문구를 다시 쓴다. 수치·단위·조건·예외·금지 여부와 항목 간 관계를
   보존한다. 원문 유지 요청이 있으면 축약하지 않는다. 제목을 본문 칸에 몰거나 필수 내용을 삭제하지 않는다.
2. 의미를 보존하며 줄여도 맞지 않으면 적합한 페이지를 `duplicate`하고 의미 단위별로 나눈다.
   원본과 복제본의 `replacements`를 각각 채우고 `coverage.at`을 실제 배치한 최종 라벨(`0`, `0#2` 등)로
   갱신한다. 같은 내용을 그대로 복제하거나 하나의 필수 항목을 양쪽 페이지에서 빠뜨리지 않는다.
3. 사용자가 한 장·페이지 수 고정을 지정했다면 임의로 페이지를 늘리지 않는다. 허용된 문구 조정과 기존
   영역 내 재배치로도 해결되지 않을 때만 페이지 수 또는 템플릿 변경 중 필요한 결정을 확인한다.
4. 수정한 plan을 재검증한다. 같은 입력을 반복하거나 `force`로 넘치던 내용을 그대로 저장하지 않는다.
   `valid=true`여도 남은 텍스트 경고와 확인된 시각 오류를 검토한다. 해결되지 않으면 문제 위치와 대안을 알린다.
