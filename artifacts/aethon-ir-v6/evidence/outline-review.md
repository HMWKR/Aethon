# Aethon v6 IR 장표 개요

기준: 2026 창업아이디어 경진대회 8분 발표, 본문 15장과 질의응답용 부록 3장. v5의 발표자 노트·최종 렌더·기술 경계와 사용자 요청을 기준으로 정리했다. 각 장은 핵심 주장 하나에 집중하고, 숫자와 기능의 상태는 가까운 곳에 표시한다.

## 본문

### 01. Aethon은 한 캐릭터의 다음 음악영상까지 이어주는 작업대입니다
- 본문: 개인 VTuber·소규모 버추얼팀을 위한 AI 음악영상 제작 작업대. 이성민 · RealizeSoft 대표 · 경복대학교 소프트웨어융합학과.
- 그래픽: 사용자 제공 Aethon 흑백 아이콘을 크게 배치한 표지. 실제 제품 이미지가 있다면 보조로 사용.
- 상태: 제품 소개이며 서비스 성과가 아님.

### 02. 제작 과정의 맥락을 사람이 다시 이어야 합니다
- 본문: 음원·IP와 자료를 준비하고, 여러 도구에서 생성·편집한 다음, 선택과 수정 이유를 전달해야 합니다. 곡이 바뀌어도 캐릭터와 제작 맥락은 이어져야 한다는 문제 가설입니다.
- 그래픽: 준비 → 제작 → 검토의 3단계 과정과 단계별 한 줄 설명.
- 근거: 에덴월드 공개 인터뷰 기반 과업 해석; Aethon 고객 인터뷰 결과 아님.

### 03. 동일한 IP로 반복 제작하는 창작자부터 검증합니다
- 본문: 개인 VTuber와 소규모 버추얼팀의 공개 사례에는 동일 IP로 곡을 이어 만들고 작업을 조율하는 과정이 나타납니다. 한 곡의 완주와 다음 곡의 재사용을 초기 검증 단위로 삼습니다.
- 그래픽: 반복 제작·운영자의 조율·검증 단위의 3카드, 별도 작은 견적 사례 카드.
- 근거·조건: 밍글스튜디오 프리미엄 MV 예상 200만~400만 원은 VAT 별도·제작 범위에 따라 달라지는 단일 사례; 시장 평균·Aethon 절감액 아님. 타깃과 구매 의향은 가설.

### 04. 기획부터 승인까지 제작 흐름을 연결합니다
- 본문: IP·음원 입력 → 대화형 AI 기획 → 영상 생성·편집 → 사람의 검토·출력으로 작업을 연결합니다. 기획용 대화 모델과 영상 생성 모델은 서로 다른 역할입니다.
- 그래픽: 사용자 흐름 4단계 화살표. 현재 구현 및 개발 목표와 미검증 상태를 별도 라벨로 구분.

### 05. 장면과 Take를 한 화면에서 검토합니다
- 본문: 내부 시험 화면에서 장면을 선택하고 Take를 비교하며 타임라인과 승인 상태를 살펴볼 수 있습니다. 화면에 나타나는 패턴은 합성 시험 미디어입니다.
- 그래픽: Aethon 실제 내부 시험 화면을 크게, 선택·비교·승인 위치만 짧게 주석 처리. 사용자 시연 영상은 추후 제공 시 추가.
- 근거: v5 노트의 2026.10.26 내부 시험 화면; 실제 AI 생성물이나 고객 사례로 표기하지 않음.

### 06. 프로토타입 개발과 제한 시험을 진행했습니다
- 본문: IP·음원·샷·Take, 편집·승인·작업 상태와 FFmpeg 출력·복구를 구현 중입니다. 합성 음원·로컬 모션 3초 MP4 기록과 별도 브라우저의 2초 편집 출력 기록이 있습니다.
- 그래픽: 현재 코드 / 제한 시험 / 다음 검증 3열; 3초·2초는 크고 명확하게 표시.
- 상태: Claude 제한 시험 기록과 일반 사용자 연결을 구분; 영상 생성 모델 실제 호출 검증 미완료. 고객 인터뷰·시험 고객·매출 없음. 2026.10.27 QA 기록이며 발표자료 제작 과정에서 시험을 재실행하지 않음.

### 07. 산업 지표와 도달할 시장을 구분합니다
- 본문: 2024년 글로벌 버추얼 크리에이터 300개 표본의 영상·라이브·Shorts 합산 조회는 150억 회를 넘었습니다. 2025년 국내 대중음악산업 매출은 전년 대비 15.8% 증가했습니다.
- 그래픽: 두 개의 큰 숫자 카드와 TAM·SAM·SOM의 범위 설명 3단계. 중첩원을 쓴다면 원의 면적은 금액 비율이 아님을 명시.
- 근거·조건: YouTube Culture & Trends 2025.04.17 / KOCCA 2026.08.18, 각각 2024 표본·2025 매출 기준. 두 지표는 Aethon TAM이 아님. 고객 수 × 연간 제작 빈도 × 1회당 도구 지출; 시장 금액 미산정.

### 08. 대안별로 제작 맥락을 관리하는 방식이 다릅니다
- 본문: 개별 생성·편집 도구와 전문 외주는 서로 다른 방식으로 작업을 수행합니다. Aethon은 IP·장면·Take·승인 기록을 연결해 다음 제작에 재사용하는 것을 목표로 합니다.
- 그래픽: 네이티브 비교표 — 열: 개별 도구 / 전문 외주 / Aethon 목표; 행: 준비·제작 / 선택·수정 / 다음 제작.
- 상태: 타사의 모든 기능 부재나 Aethon의 품질·가격·시간 우위를 단정하지 않음.

### 09. 작업대 구독과 생성 사용량 과금을 검증합니다
- 본문: 프로젝트·IP·버전·승인 관리에는 구독을, 모델 호출과 영상 처리에는 사용량 기반 과금을 가설로 검토합니다. 가격·과금 단위·마진은 미확정입니다.
- 그래픽: 구독 + 사용량 구조와 ‘승인 결과물당 비용 = (생성·재시도 + 편집·처리 + 저장·전송 + 지원 비용) ÷ 같은 기간 승인 결과물 수’ 산식.
- 상태: 실제 청구 초수와 최종 채택 영상 길이를 구분해 향후 검증.

### 10. 현재와 향후 시스템을 같은 경계로 설명합니다
- 본문: 현재 로컬 구현과 향후 확장 검토안을 사용자 / Aethon 플랫폼 / 외부 모델·서비스로 나누어 보여줍니다. 대화형 AI는 기획·도구 요청, 영상 모델은 별도의 생성 작업을 맡습니다.
- 그래픽: 위 현재·아래 향후의 2행 아키텍처, 세로 영역은 사용자 / 플랫폼 / 외부 서비스. 연결선과 기술 아이콘을 각 책임 블록 안에 배치.
- 기술 상태: 현재 코드 확인 HTML·CSS·JavaScript, Python HTTP, SQLite·로컬 파일, FFmpeg; 향후 Next.js·FastAPI·PostgreSQL·AWS·Databricks·외부 GPU는 도입 검토. LangChain은 현재 사용으로 확인되지 않아 제외. 실제 제한 Claude 시험과 일반 사용자 연결 미완료를 구분.

### 11. 기획 모델과 영상 모델을 각각 평가해 고도화합니다
- 본문: 권리가 확보된 데이터와 학습이 허용된 교사 모델을 전제로 미세조정·증류를 검토합니다. 기획용 언어 모델과 이미지·영상 모델을 각각 평가하고, 운영 시 버전·배포·롤백을 관리할 계획입니다.
- 그래픽: 데이터 → 언어 / 이미지 / 영상 모델 → 공통 평가 → 운영의 분기·합류 그림. Databricks·MLflow는 향후 검토 라벨.
- 상태: 장기 R&D 제안; 교사 모델의 계약·학습 허용 조건 확인 필요. 자체 모델 완성, 품질·비용 우위, 외부 API 완전 대체는 미검증.

### 12. 한 곡의 사용과 다음 곡의 재사용을 검증합니다
- 본문: 제작 과정 인터뷰 후 같은 IP의 한 곡을 기획부터 출력까지 관찰합니다. 다음 곡에서의 정보 재사용과 지불 의향을 확인할 계획입니다.
- 그래픽: 문제 인터뷰 → 한 곡 사용 시험 → 다음 곡·유료 의향의 3단계와 측정 지표.
- 상태: 미실행 계획; 대표가 개인 VTuber·버추얼팀 활동 채널과 음악 제작 커뮤니티에 접근하며 개발과 병행.

### 13. 검증 결과에 따라 제품과 팀을 확장합니다
- 본문: 핵심 흐름을 완성하고 제작자 완주를 검증한 뒤, 반복 유료 사용과 비용을 확인합니다. 권리 데이터·평가셋과 모델 병목을 확인하면 특화·확장을 검토합니다.
- 그래픽: 4단계 로드맵 또는 네이티브 표 — 단계 / 확인할 조건 / 필요 역할.
- 상태: 진입 조건과 협업·채용 제안이며 일정·인원·예산 미확정.

### 14. 데이터 경험을 가진 1인 대표가 제품과 검증을 이끕니다
- 본문: 이성민 대표는 경복대학교 소프트웨어융합학과 소속이며 데이터엔지니어 직무와 한화 포탈 데이터 엔지니어링 경험을 갖고 있습니다. RealizeSoft 팀의 2026 U300 Academy 대상 및 경기북동부 청년창업챌린지 IR 데모데이 기술상 이력이 있습니다.
- 그래픽: 대표의 현재 역할·관련 경험과 수상 2건의 공식 명칭을 나란히. 수상 근거는 경복대학교 보도.
- 상태: 대표 1인 운영; 과거 RealizeSoft 팀 이력과 현재 Aethon 고객·매출 실적 구분. 본인 제공 자격은 부록에 명시.

### 15. 실제 제작자의 반복 사용을 다음 성과로 확인합니다
- 본문: 초기 제작자 연결, 영상 제작 실무 피드백, 사업화·기술 멘토링을 요청합니다. 제품 완결, 제작자 작업 관찰, 실제 생성·재시도·저장·지원 비용 검증을 우선합니다.
- 그래픽: 필요한 연결 / 확인할 성과의 2열과 Aethon 마무리 메시지.
- 상태: 지원·투자 요청 금액과 배분액 미확정.

## 부록

### 16. 향후 비동기 영상 제작의 완료 조건을 관리합니다
- 본문: 작업 요청·영상 생성·S3 업로드 알림과 별도의 모델 작업 상태를 확인하고, 파일·상태·승인 검증 후 합성합니다. 중복 이벤트와 재시도는 멱등 처리하며 최종 완료를 S3 업로드만으로 판정하지 않습니다.
- 그래픽: 사용자 / Aethon / 외부 GPU·AWS의 넓은 시스템 구성도; 화살표에 요청·업로드·상태·검증 명시.
- 상태: 전체 향후 도입 검토안; AWS 이벤트 처리·RunPod·진행률 채널은 공식 문서 범위에 맞게 표현.

### 17. 대표 역량과 단계별로 보강할 역할을 제시합니다
- 본문: 대표의 경력·자격은 본인이 제공했으며 네트워크관리사 2급은 국가공인 자격입니다. 영상 제작·UX 리서치, 고객 운영·사업개발, ML·영상 생성·MLOps는 병목과 자금에 맞춰 협업·채용을 검토합니다.
- 그래픽: 현재 대표 1인 / 향후 확보할 역할의 2열 표.
- 상태: AI프러덕션 기획자 1급과 Databricks Professional은 사용자 제공 표기이며 발급기관·정확한 종목명 확인 전. 채용 확정 아님.

### 18. 숫자와 구현 상태의 출처를 제공합니다
- 본문: YouTube·KOCCA 산업 지표, 밍글스튜디오 견적, 공개 타깃 사례, 저장소·QA와 수상 보도를 구분해 제시합니다. 외부 통계·회사 기록·미검증 가설의 출처와 기준일을 명시합니다.
- 그래픽: 출처 / 측정 범위 / 기준일의 네이티브 표. 상세 URL은 편집 가능한 노트 또는 별도 근거 문서에 둠.
- 상태: 외부 통계는 자사 실적이 아니며 고객·매출·절감률 수치는 없음.

## 템플릿 적용 및 8분 발표 기준

- 숫자 150억 회+, 15.8%, 200만~400만 원, 3초·2초는 범위·출처·시점을 숫자 가까이에 둔다. 시장 중첩원은 규모 비율로 받아들여지지 않도록 명확한 각주를 붙인다.
- 실제 화면은 5쪽에 크게 배치하고 작은 사진 네 장으로 나누지 않는다. 새 사용자 영상을 받기 전에는 삽입 예정으로 둔다.
- 10쪽은 사용자·플랫폼·외부 서비스를 분리하고 현재와 향후를 동시에 보여준다. 복잡한 작업 큐는 16쪽 부록으로 분리한다.
- 12쪽은 검증 활동, 13쪽은 그 결과에 따른 단계 진입 조건이므로 중복 설명을 줄인다. 현재 1인 체제·과거 수상·향후 역할을 혼동하지 않는다.
- 발표 예상: 1쪽 10초, 2~3쪽 각 30초, 4쪽 35초, 5쪽 40초, 6쪽 45초, 7~8쪽 각 30초, 9쪽 35초, 10쪽 40초, 11쪽 25초, 12쪽 35초, 13~15쪽 각 25초. 합계 7분 40초 + 전환 여유 20초. 실제 영상 재생 시 시간을 다시 배분한다.
- 시각 참고: 웨인힐스 2023 IR 원본 p2·9·11의 실제 화면·흐름, 툰스퀘어 2024 IR p10~13의 문제와 솔루션 동일 단계, 헤드리스 공개 원본 p13의 플랫폼 경계. 타사의 실적이나 비용·효율 수치는 Aethon으로 옮기지 않는다.
