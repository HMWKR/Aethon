## 핵심 개념

### 템플릿

미리캔버스가 제공하는 디자인 원본이자 새 디자인의 시각적 출발점이다. 어떤 부분을 유지하고
변경할지는 사용자의 콘텐츠와 디자인 목적에 따라 정한다.

### Manifest

템플릿 JSON에서 모델이 콘텐츠 배치와 구조 변경을 판단하는 데 필요한 정보만 추린 요약이다.
페이지, 텍스트 슬롯, 노드, 그룹, 차트와 색상표를 설명한다. 디자인 JSON의 UUID 대신 manifest가
제공하는 짧은 식별자를 사용한다.

### Plan

템플릿을 사용자 콘텐츠로 바꾸기 위한 선언형 JSON 객체다. 모델은 디자인 JSON을 직접 만들지
않고 `replacements`, `keep`, `display_copy`, `page_ops`, `recolor`, `coverage`, `sources`와 `notes`로
변경할 내용을 표현한다. 서버가 이 객체를 템플릿에 적용한다.

예를 들어 manifest의 `0n2:0`이 표지 제목 슬롯이고 최종 페이지 라벨이 `0`이라면 다음과 같이 작성한다.
이 예시는 `prepare_design_plan`이 돌려준 골격에서 `replacements`의 값과 `coverage`의 `at`만 바꾼
모습이다.

```json
{
  "replacements": {
    "0": { "n2": "2026년 제품 전략" }
  },
  "coverage": [
    { "src": "제품 전략 발표 제목", "at": "0" }
  ]
}
```

`replacements`는 골격이 준 대로 페이지 → 노드 → 런 순으로 접혀 있다. 슬롯 id `2n8:1`은 페이지 키
`"2"` 아래 노드 키 `"n8"`의 배열 1번째 값이다. 값이 문자열이면 런 0 하나뿐인 노드다. 골격의 모양과
값의 자리를 그대로 두고 값만 바꾼다.

```json
{"replacements": {"2": {"n19": "제목", "n8": ["첫 런", "둘째 런"]}}}
```

`keep`, `page_ops`, `recolor`, `notes`는 필요할 때만 넣는다. `coverage`는 사용자 원고나 모델이 작성한
콘텐츠에 의미 단위가 하나라도 있으면 넣는다. 사용자 요구사항을 그대로 반영하지 못했다면 내용을
조용히 바꾸지 않고, 무엇을 어떻게 대신했는지 `notes`에 기록한다. 템플릿을 변경한 사실 자체는
`notes`에 기록하지 않는다.

## 차트 편집 가능 여부 확인하기

검색 결과에는 차트 수와 편집 가능 수가 없다. 차트 데이터를 바꿔야 하는 요청이면 템플릿을 선택한 뒤 manifest에서 확인한다.

- manifest의 `nodes[].chart.editable`은 필드가 없으면 편집 가능하고 `false`이면 편집 불가다.
- 필요한 편집 가능 차트가 없으면 안내서 `design/plan-data`의 "차트 작성 규칙"에 따라 `chart_create`와 배치를 검토한다.
  사용자가 기존 차트의 유지를 명시했다면 임의로 대체하지 않고 가능한 대안을 확인한다.
  그 밖에 새 차트로도 요구를 충족할 수 없으면 아래 "콘텐츠 중심 재구성"에 따라 페이지를 다시 고르거나 사용자에게 필요한 변경을 확인한다.

## 콘텐츠와 페이지 구성하기

모든 타입의 최종 디자인은 최대 30페이지로 제한한다.

manifest의 구조와 용량, 원본 썸네일의 실제 배치를 함께 보고 콘텐츠의 관계와 분량에 맞는 페이지를 고른다.
원본에서 글자가 비정상적으로 겹치거나 잘리거나 배치가 명백히 깨진 페이지는 선택하지 않는다. 의도된 장식이나 겹침, 낮은 썸네일 해상도를 결함으로 오인하지 않는다.
썸네일을 받지 못한 페이지는 결함으로 단정하지 않고 manifest로 판단한다.

표·차트가 필요한 원고는 기존 데이터 요소나 내용에 맞는 빈 영역이 있는 페이지를 우선 선택한다.
빈 영역은 본문 페이지(제목 아래에 소제목·본문·카드·데이터 요소가 놓이는 구조)에서 찾는다. 템플릿에 표지, 목차, 간지, 마무리 같은 역할 페이지가 있으면 그 페이지는 큰 띠와 제목, `role: watermark` 장식 글자, 작성자·연락처 슬롯만 있어 빈자리가 넓어 보여도 새 표·차트 자리가
아니며, 복제해서 데이터 페이지로 쓰지 않는다. 기존 표·차트가 있는 페이지, 본문 영역이 있는 페이지 순으로 고르고,
그런 페이지가 모자라면 본문 페이지를 복제한다.
공간 확보는 안내서 `design/plan-data`의 "표 영역 확보와 묶음 이동"의 순서를 따른다. 역할이 불명확한 요소를 삭제해야 하는 페이지는 선택하지 않는다.
원고에 제목이 있으면 템플릿의 제목 페이지를 첫 장으로 쓴다. 영문 조형이나 장식 런(`role: decor`)이 있어도 제외 사유가 아니다.
제목 페이지가 명백히 깨졌다면 제목 역할에 맞는 정상 페이지로 대체한다.
사용자가 특정 페이지를 지정했다면 임의로 제외하지 않고 원형을 보존하며 배치와 분할을 조정한다. 지정한 페이지가 깨졌다면 문제와 대체안을 알리고 변경 여부를 확인한다.
충족하기 어려운 제약은 사용자에게 알린다.

`replacements`를 작성하기 전에 사용자 콘텐츠를 페이지와 페이지 안의 구조에 먼저 배치한다.
구조가 정해진 뒤에 텍스트를 작성해야 삭제하거나 복제한 페이지와 요소의 슬롯을 정확하게 가리킬
수 있다. 배치는 콘텐츠 항목에서 페이지로 향하는 방향으로 진행한다. 템플릿 페이지를 차례로 훑으며
채우면 자리를 얻지 못한 항목이 조용히 사라진다.

다음 중 하나면 아래 1단계에 들어가기 전에 `get_miricanvas_guide`로 `design/plan-data`를 읽는다. 조건에 들지 않으면 읽지 않는다.

- 사용자가 표나 차트, 또는 그 타입을 요청했다.
- 원고에 같은 지표의 수치가 셋 이상인 계열이 있다.
- 위 기준으로 고른 후보 페이지 가운데 manifest에 `chart`가 있는 노드나 `TableItem` 노드를 가진 페이지가 있다.

1. 사용자 콘텐츠를 제목, 도입, 핵심 항목, 데이터, 요약과 CTA처럼 의미 단위로 나눈다.
   수치가 있는 단위는 본문을 쓰기 전에 안내서 `design/plan-data`의 "데이터로 표·차트 새로 만들기"에 따라 데이터 묶음별 표현 방식과
   대상 페이지·기존 요소 또는 생성 연산을 정한다. 텍스트 슬롯부터 채운 뒤 남는 공간에 데이터를 넣지 않는다.
2. 각 의미 단위를 가장 잘 표현하는 템플릿 페이지에 배치하고 전체 순서를 정한다.
   manifest와 썸네일로 원본 페이지의 실제 구성을 비교해, 항목의 정보 관계(목록, 절차, 비교, 서술, 수치)와 분량에 맞는 다양한 레이아웃을 활용한다.
   반복 구성이 필요한 콘텐츠는 같은 레이아웃을 재사용하며, 다양성을 위해 부적합한 페이지나 불필요한 장을 넣지 않는다.
   한 원본 페이지가 최종 디자인의 과반(5장 이상)을 차지하면 `layout_repeat` warning이 되므로, 원고가 균질한 반복이 아닌데 한 레이아웃만 복제하고 있지 않은지 확인한다.
   템플릿 페이지를 차례로 훑으며 원고를 순서대로 붓지 않는다.
   절차, 흐름, 구조, 관계, 순서처럼 그림으로 보여 줄 의미 단위는 먼저 그 구조를 표현한 템플릿 페이지(프로세스, 타임라인, 조직도,
   비교 레이아웃 등)에 배치한다. 아래 중 하나일 때만 내용을 SVG 그림으로 직접 그려 사진이나 일러스트 자리에 넣는다.
   - 사용자가 그림이나 도식으로 그려 달라고 했다. 이때는 그 구조의 페이지가 있어도 그린다.
   - 그런 구조를 표현한 페이지가 템플릿에 없다.
   - 칸 수가 맞지 않고 복제나 삭제로도 맞출 수 없다. 예: 7단계 절차인데 4단계 페이지뿐이고 단계 묶음을 복제할 수 없다.
   - 연결선이 얽힌 시스템 구성도처럼 관계가 복잡해 텍스트 슬롯과 기존 도형으로는 표현할 수 없다.

   그릴 때는 `design/plan-image`의 "직접 그릴 그림"을 따른다. 아직 읽지 않았으면 이때 `get_miricanvas_guide`로 읽는다.
   넣을 사진이나 일러스트 자리가 없으면 그리지 않고 텍스트 구성으로 둔다. 사용자가 그려 달라고 한 그림은 아래 "콘텐츠 중심 재구성"에 따라 페이지를 다시 고른다.
3. 사용하지 않는 페이지는 `delete` 또는 `reorder`로 제외한다. 필요한 레이아웃이 부족하면
   `duplicate`를 사용하거나, 다른 페이지의 차트·표 블록을 `place_block`으로, 그 밖의 요소를
   `copy_nodes`로 가져온다. 요소 이동, 복제와 삭제는 썸네일의 시각적 묶음을 manifest의 node, group, box와 대조해 정한다.
   정확한 식별자, 좌표와 용량은 manifest와 scaffold를 따른다.
4. 카드, 표의 행이나 차트 카테고리처럼 페이지 안의 반복 구조를 콘텐츠 개수에 맞춘다. manifest에
   `groups`가 있으면 `set_group_count`를 우선 사용한다. 차트의 타입·계열·카테고리는
   안내서 `design/plan-data`의 "차트 작성 규칙"에 따라 원고에 맞춘다.
5. 페이지와 구조가 확정된 뒤 `prepare_design_plan`으로 골격을 받아 `replacements`를 채운다. plan을
   빈 문서에서 작성하지 않는다. 복제본(`#2`)이나 `place_block`으로 새로 생긴 슬롯만 골격에 없으므로
   직접 더한다. 골격의 값을 바꾸지 않고 두면 미교체로 빈값 처리되어 `expose` error가 된다. 쓰지
   않을 슬롯은 범용 라벨만 `keep`으로 남기고, 그 밖에는 페이지 `delete`로 처리한다.
6. 최종 페이지 라벨을 기준으로 모든 의미 단위의 `coverage`를 작성한다.

### 콘텐츠 중심 재구성

- 사용자의 콘텐츠 구조, 정보의 우선순위, 브랜드와 디자인 목적을 템플릿의 기존 구성보다 우선한다.
- `delete`, `duplicate`, `reorder`, `place_block`, `copy_nodes`, `resize_nodes`, `duplicate_nodes`,
  `delete_nodes`, `move_nodes`와 `align_nodes`를 사용하여 페이지와 요소를 적극적으로 재구성한다.
- 템플릿의 기존 문구 분량에 콘텐츠를 맞추기보다 콘텐츠를 먼저 구성하고, 필요한 페이지와 요소
  구조를 만든 뒤 최종 슬롯 용량에 맞게 문장을 다듬는다.
- 템플릿의 노드와 그룹을 복제하거나 조합하는 방법을 우선 사용한다. 표·차트를 새로 만들 때는
  전용 생성 연산을 사용하고, 그 외 구조를 기존 요소로 만들 수 없을 때만 `add_nodes`를 쓴다.
- 원고에 없는 구조 틀(비교표, 주간 계획표 등)을 새로 만들지 않는다. 원고에 있는 표·수치 계열을
  표·차트로 표현하는 것은 이 금지 대상이 아니다. 표현 선택은 안내서 `design/plan-data`의 "데이터로 표·차트 새로 만들기"를 따른다.
  페이지 구성은 원고의 항목 단위를 따른다. 새 틀을 만들면 원고에 없는 칸은 창작으로 채우게 되고,
  틀에 넘치는 원고는 삭제로 흐른다.

원고가 있으면 템플릿의 기존 페이지, 카드나 차트 개수에 맞추려고 사용자 콘텐츠를 임의로 추가하거나 생략하지
않는다. 원고 없이 주제만 받았으면 안내서 `design/create-from-template`의 "원고 없이 주제만 받았을 때"에 따라 템플릿 구성을 개요로 삼는다.
구조가 콘텐츠를 수용하지 못하면 같은 템플릿의 다른 페이지를 쓰거나 구조를 변경한다. 그래도
요구사항을 그대로 반영할 수 없다면 사용자에게 필요한 변경을 확인하고, 결정한 대안과 이유를 `notes`에 기록한다.
템플릿 변경과 재검색은 안내서 `design/create-from-template`의 "템플릿 검색과 선택"을 따른다.
`notes`는 변경 사실을 기록하는 수단이며 사용자 요구나 데이터 범위를 임의로 바꾸는 허가가 아니다.

## Manifest 읽기

### Canvas와 palette

- `canvas`는 페이지 크기다. 요소를 가운데 정렬하거나 캔버스를 벗어나는지 판단할 때 사용한다.
  페이지 크기가 서로 다르면 해당 페이지에 별도 `canvas`가 있다.
- `palette`는 디자인에 쓰인 색을 사용 횟수 순서로 보여준다. `roles`는 색이 텍스트, 면, 선,
  일러스트, 차트 등에 어떻게 쓰였는지 나타낸다. `neutral: true`는 무채색이다.

### Nodes와 groups

- `pages[].nodes[]`는 도형, 선, 아이콘과 차트 같은 구조 노드다. `id`는 `0n1`, `12n7` 같은
  짧은 식별자다. `page_ops`에는 이 식별자를 그대로 사용하고 UUID를 만들지 않는다.
- `box`는 캔버스 기준의 `left`, `top`, `width`, `height`다. 자식 노드에도 절대좌표가 들어 있다.
- `parent`가 있으면 다른 노드의 자식이다. 자식은 부모를 이동하거나 복제할 때 함께 처리된다.
- `pages[].groups[]`는 서버가 미리 찾은 요소 묶음이다. `19g3` 같은 그룹 식별자를 노드 목록
  대신 사용하면 카드나 열에 속한 작은 요소를 빠뜨리지 않는다.
- 그룹의 `axis`와 `count`는 반복 방향과 요소 개수를 나타내고, `items`는 각 반복 요소에 속한
  노드 식별자를 나열한다.
- `resizable: false`이면 연결 구조 때문에 요소 개수를 안전하게 바꾸기 어렵다. `connectors`가 있으면
  반복 요소 사이를 잇는 노드이며, `set_group_count`가 개수와 위치를 함께 조정한다.
- `TableItem` 노드에는 `table`이 있다. `rows`, `columns`와 함께 `cells`가 있으면 행 우선 2차원
  배열이고 각 칸이 셀 노드 식별자다. 행 연산의 행 번호는 이 배열의 인덱스이며, 0행이 헤더인 경우가
  많다. `table.resizable: false`와 `reason`이 붙은 표(신형 표 또는 병합 셀이 있는 표)는 행을 추가하거나
  지울 수 없고 `cells`가 없을 수 있다. 셀 텍스트는 일반 슬롯이므로 `replacements`로만 바꾼다. 행 수가
  콘텐츠와 맞지 않으면 셀 안에서 줄을 합치거나 그 페이지를 사용하지 않는다.
- `pages[].blocks[]`는 페이지를 넘어 통째로 옮길 수 있는 차트·표 블록이다. `id`는 `7b1`처럼
  `<페이지>b<순번>`이고, `kind`는 차트와 그 위에 얹힌 라벨을 묶은 `chart` 또는 표와 셀 텍스트를 묶은
  `table`이다. `node`는 중심 노드 식별자이고, `box`는 `nodes[].box`와 같은 좌표계로 표현한 블록 전체의
  자리다. 블록은 `place_block`으로 옮기며, 블록 `box`와 자리 `box`를 비교해 들어가는 조합만 계획한다.

### Slots

- `pages[].slots[]`는 교체할 수 있는 텍스트다. `slot`은 `0n2:0`처럼 노드 식별자와 텍스트
  리프 인덱스를 합친 값이다.
- `text`는 템플릿의 예시 문구이며, `fontSize`와 `box`는 제목, 본문, 수치와 라벨의 역할을
  판단하는 근거다.
- `chars`는 현재 글자 크기와 렌더 폭으로 계산한 텍스트 상자 전체의 대략적인 한글 글자 수다. 같은
  노드의 런 여러 개에 같은 값이 붙어 있어도 합계가 이 값을 넘지 않게 작성한다. 영문과 숫자는 같은 폭에 한글보다 약 1.7배 많이 들어갈 수 있다. 문장 구조상
  필요한 작은 차이는 자동 글자 축소가 처리할 수 있다.
- `item`은 슬롯이 속한 반복 그룹 항목이고, `para`는 같은 줄에서 이어지는 텍스트 리프의 문단
  식별자다. 같은 `para`의 슬롯들은 화면에서 한 줄로 이어 붙는 런이므로, 이어 읽어 자연스러운 한
  문장이 되도록 채우고, 원본이 공백으로 끝나는 런은 새 텍스트도 공백이나 구분자로 끝낸다.
  다만 다음 런이 조사로 시작하면 앞 런 끝에 공백을 두지 않는다(`["신청 방법", "을 확인하세요"]`이고
  `["신청 방법 ", "을 확인하세요"]`가 아니다). 경계에 공백이 겹치거나 조사 앞에 공백이 남으면 서버가 지우고
  `run_space` info로 알린다.
  `para`가 바뀌는 곳은 줄이 바뀌는 자리다. 한 문장을 여러 `para`에 걸쳐 잘라 넣으면 문장 중간에서
  줄이 바뀌고 어절 하나만 남는 줄이 생기므로, 문장이나 구는 한 `para` 안에서 끝낸다. 템플릿이 줄
  균형을 맞추려 문장 중간에서 나눈 본문은 서버가 문단을 하나로 이어 폭에 맞춰 다시 줄바꿈한다
  (`soft_wrap` info).
- `lineMarkers`가 있는 슬롯은 줄마다 꺾쇠·점 같은 표식이 붙은 목록 본문이다. 값은 표식 수이며 쓸 수 있는
  줄 수다. 문장 하나를 `para` 하나에 두고 문장 수는 표식 수 이하로 쓴다. 문장 하나가 상자 폭에서 한 줄을
  넘지 않게 짧게 쓴다. 서버는 문장마다 문단이 되게 다시 나누고(`list_split` info) 문장 수보다 많은 표식을
  지우며(`marker_trim` info), 줄 수가 표식보다 많으면 `list_overflow` warning으로 알린다.
- 라벨, 값, 설명의 짝은 같은 `item`이거나 `box`가 가까운 슬롯끼리 묶는다. 노드 식별자의 순번은
  캔버스 배치와 무관하므로, 식별자가 이웃이라는 이유로 같은 카드로 취급하지 않는다.
- 숫자만 있는 슬롯(`24,000`, `78.0`)은 큰 숫자를 보여주는 자리이며 옆에 단위가 별도 노드로 붙어
  있는 경우가 많다. 숫자 슬롯에는 숫자만 넣고 설명은 같은 `item`의 라벨 슬롯에 넣는다. 단위를 품은
  값(`0.31초`)을 넣으면 서버가 옆 단위 노드를 비우고, 숫자가 아닌 글을 넣으면 슬롯이 비워지거나
  `role` finding이 남는다.
- `fontSize`가 캔버스 높이의 1.5% 미만(1080 기준 16 미만)인 슬롯은 작게 보여 잘 읽히지 않는다.
  그 슬롯에는 핵심 논지를 두지 않고 보조 정보만 넣는다.
- 서버는 카드 안의 여러 줄 본문을 축소하기 전에 가용 폭을 검토한다. 이웃과 내부 여백을 지키면서
  같은 글자 크기의 예상 줄 수가 줄어들 때만 상자를 넓히고 `text_widen` info로 알린다.
  명시적 개행과 문단은 그대로이며, 이 안내는 최종 렌더의 가독성을 보증하지 않는다.
- 원본이 영문인 슬롯에 한글을 넣을 때는 글자 수를 원본의 2/3 이하로 잡는다.
- `role: pagenum`은 서버가 최종 순서에 맞춰 자동으로 바꾸는 페이지 번호다. `replacements`나
  `keep`으로 지정하지 않는다.
- `role: running`은 여러 페이지의 같은 자리에 같은 글로 반복되는 라벨(브랜드명, 문서 제목, 세로 러닝 헤드)이다.
  골격은 한 번만 묻고 서버가 그 값을 나머지 페이지에 복사한다. 본문 조각을 넣지 않으며, 두 페이지에 다른 값을 넣으면
  `running` error가 된다. 템플릿 값을 그대로 둘 것이면 `keep`에 넣는다.
- `role: curved`는 곡선을 따라 그리는 텍스트다. `chars`가 원문 글자 수이고 그 이내의 한 줄만 들어간다. `role: decor`는
  글꼴이 다른 한두 글자의 장식 런이다. 원고 제목을 장식 런과 바로 뒤 런에 나눠 이어 쓴다(예: `사` + `활과 정석`).
  한글이 들어오면 서버가 장식 런을 같은 줄의 글꼴과 크기로 맞춘다. 영어 작성 안내가 없으면 원고에 영문 표현이 있을 때만 장식 런에 영문
  앞 글자를 정확히 `chars`자 넣어 장식 글꼴을 살리고, 원고에 없는 영문을 만들지 않는다. 영문 글자 수가 다르면
  `fixed_text` error로 저장이 보류된다.
  영어 작성 안내가 있으면 원고의 뜻을 영어로 옮기고, 장식 런에는 앞 글자를 정확히 `chars`자 나눠 넣는다.
- `role: watermark`는 캔버스 높이의 20% 이상 글자 크기로 쓴 1~3자 장식 글자(브랜드 이니셜 "M", 장 번호 "2")다.
  콘텐츠 자리가 아니며 그 글자가 덮는 영역은 빈 영역이 아니다. 바꿀 때는 같은 글자 수의 이니셜·번호만 넣는다.
- 최종 결과에 남길 템플릿 원문은 모두 `replacements`로 교체하거나 `keep`으로 명시한다. 연락처처럼
  사용자가 제공하지 않은 값을 만들어야만 교체할 수 있다면 관련 라벨과 함께 `delete_nodes`로 지운다.
- 템플릿 예시 수치가 붙은 도형(도형으로 그린 막대, 게이지, "00%" 라벨)은 차트가 아니라서 서버가 수치 미교체를 잡지
  못한다. 원고에 그 자리에 넣을 수치가 없으면 라벨과 도형을 함께 `delete_nodes`로 지운다. 임의 숫자를 넣지 않는다.

### Display groups

- `pages[].displayGroups[]`는 "MARKETING STRATEGY"처럼 큰 영문 제목이 한 글자씩 또는 덩어리로
  분리된 텍스트 상자로 이루어진 대형 영문 조형 그룹이다. `id`는 `0d1`처럼 `<페이지>d<순번>`이다.
- `lines`는 화면 위에서 아래 순서의 줄이고, 각 줄의 `slots`는 왼쪽에서 오른쪽 순서의 슬롯이다.
  `text`는 현재 표시된 글자를 이어 붙인 것이고, `chars`는 그 줄에 정확히 필요한 글자 수다.
- 이 슬롯은 `replacements`로 하나씩 채우지 않고 `display_copy`로 그룹 전체의 영문 카피를 쓴다.
  상자마다 한글을 넣으면 조형이 깨지므로 서버가 `display` error로 저장을 막는다.

### Photos

- `pages[].photos[]`는 이미지 교체 후보이며 실제 검색 대상 목록은 아니다. 이미지마다 한 항목이며 그룹 안의 이미지도 따로 노출한다.
- `node`는 그 이미지이고 `box`는 그 이미지가 채우는 자리의 영역이다.
- `caption`은 주변 텍스트에서 추정한 보조 정보다. 이미지의 실제 내용으로 단정하지 않는다.

사용할 각 페이지의 `photos[]` 모든 항목을 `get_template_page_previews`로 본 원본 썸네일에서 확인하고, 이미지의 역할, 주변 콘텐츠와 새 원고를 기준으로 아래 제외 조건을 적용한다. 복제한 페이지의 이미지는 복제본마다 별도 항목으로 판단한다.
호출 수를 줄이기 위해 교체 대상을 임의로 제외하지 않는다.

**교체 대상에서 제외하는 항목**

- 삭제하기로 한 항목.
- 썸네일을 볼 수 없어 원본을 판단할 수 없는 항목.
- 로고, 불릿, 장식. 자동 검색과 교체에서는 유지한다. 사용자가 자기 이미지로 교체하라고 지정한 경우에는 안내서 `design/plan-image`의 "배치와 plan 반영"을 따른다.
- 템플릿 고유의 그림체로 다른 그래픽과 한 벌을 이루어 혼자 바꾸면 어긋나는 캐릭터/마스코트.
- 텍스트나 이미지의 바탕이나 테두리 역할만 하는 패널, 프레임.
- 원본 이미지의 대상과 장면이 그 자리의 새 콘텐츠에 명확히 맞아서 다른 요소로 대치할 필요가 없는 항목. 명확히 맞는지 애매하면 교체 대상에 넣는다.
- 사용자 지정 이미지, 요청의 핵심인 실제 대상 이미지, 그린 그림을 넣을 항목(안내서 `design/plan-image`의 "배치와 plan 반영").
  맞는 자리가 없으면 위 "콘텐츠 중심 재구성"에 따라 페이지를 다시 고르고, 그래도 없으면 안내서 `design/plan-image`의 "반영하지 못했을 때"를 따른다.

교체 대상에서 제외한 항목은 삭제 예정이거나 등록한 이미지를 넣는 경우를 제외하고 원본을 유지한다.
나머지는 배경 사진(`role: "background"`)을 포함해 안내서 `design/plan-image`의 "이미지 교체"의 "일반 교체 이미지"를 따른다.
이 절에서는 교체 대상만 정한다. 자리마다 웹 이미지를 쓸지 요소 검색을 할지와 검색어는 안내서 `design/plan-image`를 읽은 뒤 정한다.

### Charts

| manifest 필드 | 해석 |
|---|---|
| `chart.editable`, `reason` | full manifest는 `false`일 때만 편집 불가. 생략되면 편집 가능. brief의 `editable`은 boolean |
| `vizType`, `series` | 현재 타입과 계열 이름·스타일. 변경 규칙은 안내서 `design/plan-data`의 "차트 작성 규칙" 참고 |
| `datasource` | 첫 행은 헤더, 첫 칸은 빈 문자열 |
| `categoryCount` | `free`: 개수 변경 가능. `fixed`: 기존 개수 유지 |
| `overlayBands`, `overlayTexts` | 차트 위 별도 텍스트. 유지하면 슬롯도 `replacements`로 바꾼다 |
| `legend` | 차트 밖 범례. `shape`는 색 도형, `text`는 이름, `series`는 계열 순서 |

`chart.editable: false`이면 `reason`에 이유가 붙는다(게이지, 또는 옛 형식에서 변환되지 않은 차트).
텍스트만 교체하거나 다른 편집 가능 차트나 페이지를 쓴다.

`GaugeItem`은 항상 편집 불가이며 슬롯도 없다. 예시 수치가 콘텐츠와 다르면 노드나 페이지를 삭제한다.

## page_ops 작성 규칙

`page_ops`는 배열 순서대로 적용되며, 페이지 인덱스는 직전 연산까지 반영된 상태를 기준으로 한다.
지원하는 연산은 페이지(`duplicate`, `delete`, `reorder`), 표(`table_create`, `table_add_row`, `table_delete_row`, `table_set_cell_style`), 그룹
(`set_group_count`), 노드(`duplicate_nodes`, `delete_nodes`, `move_nodes`, `copy_nodes`, `resize_nodes`,
`add_nodes`, `align_nodes`), 블록(`place_block`), 차트(`chart_create`, `chart_set_data`, `chart_set_series`, `chart_set_type`), 이미지(`replace_image`),
QR 코드(`set_qr_url`)다.
표 생성은 안내서 `design/plan-data`의 "데이터로 표·차트 새로 만들기", 차트는 같은 안내서의 "차트 작성 규칙", 이미지 연산은 안내서 `design/plan-image`의 "이미지 교체"를 따른다.

- QR 코드(`nodes[].type`이 `QrcodeItem`)는 사용자가 URL을 줬으면 `{"op":"set_qr_url","page":0,"node":"0n20","url":"https://…"}`로
  바꾸고, 없으면 QR 노드를 `delete_nodes`로 지운다. 서버가 QR을 담은 빈 틀과 바로 위에 붙은 짧은 라벨을 함께 지운다.
  템플릿의 QR 주소를 그대로 두지 않는다.

```json
{"op":"duplicate","page":2}
{"op":"delete","page":4}
{"op":"reorder","order":[0,2,1]}
```

- `duplicate`는 지정한 페이지를 바로 뒤에 복제한다. 같은 페이지가 여러 장 필요하면 `count`(1~100)로 한 번에
  복제한다. `{"op":"duplicate","page":"9","count":3}`은 `9`, `9#2`, `9#3`, `9#4` 순서가 된다.
- `delete`는 지정한 페이지를 지운다. 모든 페이지를 지우는 plan은 거절된다.
- `reorder`는 나열한 페이지만 남겨 해당 순서로 배치한다.

```json
{"op":"table_add_row","page":3,"table":"3n5","copy_row":2}
{"op":"table_delete_row","page":3,"table":"3n5","row":4}
```

표의 `rows`, `columns`, `cells`와 각 슬롯의 `tableCell`을 근거로 행을 선택한다. 복제된 셀의 텍스트는
원본 셀 슬롯에 `#2`를 붙여 지정한다. 복제한 페이지의 표는 `"table":"3n5#2"`처럼 가리킨다. `table.resizable: false`인
표, 마지막 남은 행의 삭제, 범위 밖 행, `delete_nodes`로 셀을 지운 행의 복사는 거절된다. 행을 더해 표가 컨테이너를
넘치면 서버가 표 전체를 줄이고 `group` info로 누적 배율을 알린다. 원본의 0.5배 미만이 되면 거절되므로 행 수를 줄이거나
다른 페이지를 쓴다. 표가 필요 없으면 `delete_nodes`로 표를 지운다.

```json
{"op":"set_group_count","group":"5g2","count":4,"align":"center"}
```

- manifest에 `groups[].id`가 있으면 반복 요소의 개수를 바꿀 때 `set_group_count`를 우선 사용한다.
- `count`는 1 이상이어야 하고, `align`은 `center` 또는 `justify`를 사용한다.
- `resizable: false`인 그룹은 개수를 바꾸지 않는다.
- 늘어난 요소가 기존 반복 영역에 들어가지 않으면 서버가 반복 항목 전체를 같은 비율로 축소하고
  `code`가 `group`인 finding으로 축소율을 알린다. 0.5배 미만으로 줄여야 하면 서버가 거절한다. 약
  0.7배보다 작아졌다면 가독성을 확인하고, 더 적은 개수나 다른 페이지를 우선 검토한다.
- 차트가 든 아이템은 복제할 수 없으므로, 차트가 포함된 그룹은 개수를 늘릴 수 없다.
- 늘어난 아이템의 슬롯은 마지막 아이템의 슬롯 식별자에 `#k`를 붙여 지정한다.
- 같은 그룹에 수동 `delete_nodes`나 `move_nodes`도 적용해야 한다면 `set_group_count`를 먼저 실행한다.

```json
{"op":"duplicate_nodes","page":5,"nodes":["5g2"],"dx":400,"dy":0}
{"op":"delete_nodes","page":5,"nodes":["5g3"]}
{"op":"move_nodes","page":5,"nodes":["5g1"],"dx":100,"dy":0}
```

- 그룹 식별자가 있으면 이 수동 연산 대신 `set_group_count`를 사용한다. 그룹으로 탐지되지 않은
  반복 요소만 `duplicate_nodes`로 늘리거나 `delete_nodes`로 줄인다. 같은 좌표 구간의 노드를 빠짐없이
  지정한다.
- 개수를 바꾼 뒤 남은 요소는 `align_nodes`로 가운데 정렬한다. 일정 간격이 아닌 개별 배치가 필요할
  때만 `move_nodes`를 쓰며, 이때 `dx`와 `dy`는 이웃 요소의 `box` 차이에서 구한다. 계산에 확신이
  없으면 개수를 유지하고 콘텐츠를 합치거나 다른 페이지를 쓴다.
- 선과 화살표가 복잡하게 연결된 레이아웃은 배치에 종속되므로 개수를 바꾸지 않는다.

### 남은 요소 가운데 정렬하기

```json
{"op":"align_nodes","page":5,"nodes":["5n2","5n3","5g1"],"axis":"x","to":"canvas_center"}
```

- 지정한 최상위 노드(또는 그룹 식별자) 묶음의 화면 박스 합집합을 캔버스 중앙에 맞추고, 묶음 안의
  상대 배치는 유지한다. `axis`는 `x`, `y`, `both` 중 하나이고 `to`는 `canvas_center`만 지원한다.
- 이동량은 서버가 계산하므로 `dx`와 `dy`를 쓰지 않는다. 자식 노드를 지정하면 거절된다.
- 사이드바나 큰 사진처럼 한쪽 구조를 `delete_nodes`로 지운 뒤 남은 제목과 본문 묶음을 다시 중앙에
  놓는 용도다. 이렇게 옮기면 가장자리에 남은 `hole`은 해결된 것으로 인정된다.

### 다른 페이지의 블록 배치하기

```json
{"op":"place_block","block":"7b1","at":"3b1"}
```

- manifest의 `blocks`에 있는 블록을 다른 페이지의 기존 요소 자리에 넣는다. `page`는 없다. `at`은
  자리를 내줄 대상이며 블록 식별자(`3b1`) 또는 최상위 노드 식별자(`3n5`)다.
- 서버가 `at` 요소를 지우고 블록을 그 자리 중심에 맞춰 복사한다. `at`이 블록의 중심 노드이면 그
  블록 전체가 자리를 내준다. 좌표 계산은 하지 않는다.
- `blocks`에 있는 블록은 `place_block`으로 옮기고, `blocks`에 없는 요소 묶음만 `copy_nodes`로 가져온다.
- 블록이 자리보다 크면 거절된다. 크기 조절은 없으므로 `box`를 비교해 들어가는 자리를 고른다. 블록이
  자리의 1/3 미만을 덮으면 `hole`이 남으므로 크기가 비슷한 자리를 고른다.
- `at`이 자식 노드(표 셀 등)이거나 블록과 같은 페이지에 있으면 거절된다. 같은 페이지 안의 이동은
  `move_nodes`를 쓴다.
- `at` 요소를 `delete_nodes`로 미리 지우지 않는다. `at` 요소의 슬롯은 `replacements`와 `keep`에 쓰지
  않는다. `replacements`에 쓰면 `unresolved`, `keep`에 쓰면 `keep` error로 돌아온다.
- 차트 블록의 `chart_set_data`·`chart_set_series`·`chart_set_type`은 `place_block`보다 앞에 둔다. 뒤에 두면 거절된다. 원본 차트에 적용한
  데이터는 복사본에도 함께 반영된다.
- 원본 페이지는 그대로 남는다. 그 페이지를 쓰지 않으면 `place_block` 뒤에 `delete`한다.
- 복사된 블록의 슬롯은 원본 슬롯 식별자에 `#k`를 붙여 지정한다.

### 블록이 아닌 요소 가져오기

```json
{"op":"copy_nodes","nodes":["19g3"],"to_page":4,
 "to_box":{"left":975.8,"top":362,"width":838.7,"height":648},"fit":true}
{"op":"resize_nodes","page":4,"nodes":["4g1"],"scale":0.8}
```

- `copy_nodes`는 같은 템플릿의 다른 페이지에서 `blocks`에 없는 요소를 가져온다. 먼저 `delete_nodes`로
  붙일 자리를 비우고, 그 자리의 사각형을 `to_box`로 사용한다.
- 가져올 요소가 `to_box`보다 크면 `fit: true`를 사용한다. 원본 그룹과 대상 영역의 가로세로 비가
  크게 다르면 여백이 많이 남으므로 비율이 비슷한 자리나 그룹을 선택한다.
- `fit`으로 약 `0.7`배보다 작게 줄어들면 본문을 읽기 어려울 수 있다. 이 경우에는 더 넓은 자리를
  만들거나 다른 그룹을 선택한다.
- 가져올 페이지를 지우려면 `copy_nodes`를 먼저 적용한 뒤 `delete`한다.
- 복사한 요소는 이후 `page_ops`나 차트 연산으로 다시 가리킬 수 없다. 필요한 차트 데이터는
  원본 차트에 먼저 적용하고 복사한다.
- 원본 차트에 데이터를 먼저 적용하면 원본 페이지를 남길 때 그 차트에도 같은 데이터가 표시된다.
  원본 페이지에 다른 데이터가 필요하면 해당 페이지를 남기지 않거나 다른 구성을 선택한다.
- 복사한 요소는 대상 페이지의 가장 위에 배치되므로, 기존 요소를 덮지 않도록 자리를 먼저 비운다.
- `resize_nodes`는 그룹의 중심이나 지정한 `to_box`를 기준으로 비율을 유지하여 크기를 바꾼다.
  회전은 바꾸지 못하며, 크게 줄이면 글자도 함께 작아진다.
- 도형 테두리와 차트의 선·심볼 크기는 함께 축소되지 않는다. 크게 줄이면 상대적으로 굵어 보일
  수 있으므로 축소 폭을 줄이거나 다른 레이아웃을 선택한다.
- `add_nodes`는 기존 요소나 전용 연산으로 만들 수 없는 구조가 반드시 필요할 때만 사용하는 최후의 수단이다.
  `nodes`에는 원본 노드 JSON(`data.nodeType`과 `data.props`를 가진 형태)만 넣는다.
  `{nodeType:"TEXT", text, x, y}` 같은 요약 형태는 거절된다.
