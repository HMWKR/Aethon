## 데이터로 표·차트 새로 만들기

원고를 같은 비교 질문에 답하는 데이터 묶음으로 나누고, 각 묶음에 아래 표를 위에서부터 적용한다.
사용자 요청과 원고의 목적에 처음 맞는 조건을 따른다. 기존 요소의 존재만으로 표현 방식을 바꾸지 않는다.

| 조건 | 선택·행동 |
|---|---|
| 사용자가 표·차트 또는 타입을 지정함 | 지정에 따름 |
| 개별 값 조회와 추세·비교 관계 파악이 모두 필요함 | 표·차트 병용. 같은 데이터를 사용하고 역할을 나눔 |
| 개별 값 조회 또는 가격·용량·조건 등 여러 속성 대조가 주목적임 | 표 |
| 추세·크기 차이·순위·구성비 파악이 주목적임 | 차트. 정확한 값도 필요하면 지원되는 값 라벨 사용 |
| 목적이 불명확하고 동일 지표·단위의 수치 계열임 | 차트 |
| 목적이 불명확하고 서로 다른 속성·단위·설명을 함께 조회해야 함 | 표 |

단위·규모가 달라 같은 축의 비교가 왜곡되면 별도 차트로 나눈다. 단위가 다르다는 이유만으로 표로 바꾸지 않는다.
차트 타입은 "차트 작성 규칙"의 "타입 선택"을 따른다.

단일 지표라도 여러 시점·대상의 추세나 크기를 비교하면 차트를 쓴다. 정확한 수치도 함께 보여줘야 하면
차트에 값 라벨을 표시한다. 전체 값을 차트로 전달할 수 있으면 표를 중복 추가할 필요는 없다. 선택한 표현에서 원자료를 생략해도 된다는 뜻은 아니다.
개별 값 조회가 주목적일 때는 위 표 선택 조건을 따른다.
비교·조회 목적이 없는 값 한두 개는 본문으로 표현한다. 같은 지표의 수치가 셋 이상인 계열은 표·차트로 담고,
여러 계열이면 각각 적용한다. 값 나열·텍스트 격자·카드로 대신하지 않는다. 사용자 지정은 위 표를 우선한다.
수치 묶음마다 항목·시점·지표·단위·전체 값과 배치 위치를 대조한다. 원고의 중간 시점이나 일부 지표를 빼고
처음·끝 값만 남기지 않는다. 사용자가 명시적으로 요청한 요약·제외 범위는 따른다.
`series_text`는 전환 후보를 찾는 보조 검사다. 각 경고를 확인하고, 위 선택 기준상 표·차트가 필요한 실제 계열이면
전체 값을 기존 표·차트 또는 생성 연산에 먼저 담은 뒤 본문을 해석 문장으로 줄이고 재검증한다.
값을 삭제하거나 문장·슬롯으로 흩어 경고만 없애지 않는다. 날짜·식별자 등 오탐이거나 전체 값이 이미 표·차트에 있는
요약이면 해당 위치·판단 근거를 `notes`에 적는다. 사용자 지정에 따른 예외도 그 요청과 적용 위치를 적는다.
본문에 수치가 남아 있다는 사실만으로 전환 완료나 예외로 판단하지 않는다. 경고가 없어도 위 대조를 생략하지 않는다.

편집 가능한 기존 요소를 재사용하거나 `table_create`·`chart_create`로 만든다.
공간 부족·편집 불가·검증 오류가 있어도 위 선택 기준과 데이터 보존 규칙을 지킨다.
배치 제약은 표현 방식을 생략하는 조건이 아니다. 먼저 정한 데이터 묶음을 유지하며 영역·페이지·분할을 바꾼다.

작성 전과 최종 검증 전에 데이터 대응을 확인한다.

- 표·차트로 표현할 수치 묶음마다 `notes`에 원고의 묶음 이름 → 대상 페이지와 기존 요소 참조 또는 생성 연산의 위치를 기록한다.
  최종 plan에서 해당 요소·연산에 전체 데이터가 들어 있는지 대조한다. 본문의 값 나열·텍스트 격자나
  `notes`에만 적은 데이터·생성 예정 설명은 실제 표·차트 배치로 세지 않는다.
- 원고의 **항목·시점·지표·단위·값**을 함께 유지하고 표·차트·외부 라벨 간 대응을 일치시킨다.
- 시간 계열은 카테고리와 모든 계열의 값을 함께 시간순으로 정렬한다.
- 수치·단위를 임의로 환산·반올림하거나 없는 값을 만들지 않는다. 누락값을 0으로 대체하지 않는다.
- 표는 `table.cells`·`tableCell`, 차트는 `chart.datasource`·`series`·오버레이 정보로 대응을 확인할 수 있을 때만 재사용한다.
  대응이 불명확한 텍스트·도형 그래프는 라벨만 교체하지 않고, 선택한 표현 방식으로 새로 만들거나 다른 적합한 페이지를 쓴다.

- 두 연산 모두 `page`와 캔버스 안의 `box: {left, top, width, height}`를 지정한다. manifest와
  썸네일에서 제목·본문을 가리지 않는 영역을 고른다. 충돌은 "표 영역 확보와 묶음 이동"으로 해결한다.
- 차트 `box`의 폭은 그 페이지의 본문 열(소제목·본문이 쓰는 왼쪽 여백부터 오른쪽 여백까지)에 맞춘다. 옆에 본문·이미지를 두는
  두 열 배치가 아니면 한쪽에 본문 폭의 빈 영역을 남기지 않는다. `role: watermark` 장식 글자와 띠는 옆에 있는 콘텐츠로 세지
  않는다. 제목 띠·구분선·카드 경계와는 캔버스 높이의 3% 이상(1080 기준 32px) 간격을 둔다. 띠 바로 아래에 붙이거나 한쪽
  절반에만 두면 `chart_placement` warning이 된다.
  배경·텍스트 및 이들이 섞인 그룹은 공간 정리를 위해 삭제하지 않는다. 텍스트를 지워도 주변 도형은 자동 삭제되지 않는다.
  새 요소는 기존 요소보다 앞에 놓인다. 본문을 받치는 배경 카드 안에 표·차트를 놓는 것은 충돌로 보지 않으며,
  카드에 걸쳐 나간다는 오류는 `box`를 카드 안쪽으로 맞춰 푼다.
- 표: `columns`는 비어 있지 않은 열 이름 문자열 배열, `rows`는 한 행 이상이며 각 행의 칸 수가
  열 수와 같아야 한다. 셀 값은 문자열·유한한 숫자·`null`(빈 칸)이다.
  선택 필드 `font_size`의 API 허용 하한은 16, 기본값은 24다. 작성·결과 가독성 기준은 아래 배치 규칙을 따른다.
- 차트: `categories`는 비어 있지 않은 문자열·유한한 숫자 배열, `series`는 하나 이상인
  `{name, values}` 배열이다. `name`은 단위를 포함한 계열 이름, `values`는 카테고리 수와 같은
  길이의 유한한 숫자 배열이다. `type`의 기본값은 `BAR_CHART_VER`다.
  파이·도넛은 음수가 없고 양수가 하나 이상이어야 한다. 타입별 계열 수는 "타입 선택"을 따른다.
  `y_axis`·`label_position`은 "차트 작성 규칙"의 "라벨·축 옵션"을 따른다.
- 배치: 차트는 700×400 이상·페이지당 둘까지, 표는 페이지당 하나·글자 20px 이상을 기준으로 영역을 잡는다.
  표가 더 필요하거나 7열을 넘으면 다른 적합한 페이지에 나눠 배치하고, 없을 때 페이지를 복제한다.
  서버 자동 축소 후 20px 미만이거나 읽기 어려우면 "표 영역 확보와 묶음 이동"에 따라 영역·페이지를 바꾼다.
  위 선택 기준에서 표가 적합한 경우에만 열 수·셀 내용 길이·가독성·패딩에 맞춰 폭을 정한다.
  행·열이 적다고 글자나 셀을 키워 페이지를 채우지 않는다. 작은 표는 원고의 관련 해석·판단 조건과 함께 배치하고,
  표만으로 화면이 지나치게 비면 표를 유지한 채 그 구성에 맞는 다른 페이지를 선택한다.
  여백을 채우려고 원고에 없는 행·열·설명을 추가하지 않는다.
- 새 요소에는 manifest 식별자가 없다. 데이터·타입·크기는 생성 연산에서 완성하고, 같은 plan의
  `replacements`나 후속 노드·표·차트 연산으로 새 요소를 가리키지 않는다. 페이지 복제·재정렬은 가능하다.

```json
[
  {"op":"table_create","page":2,
   "box":{"left":100,"top":200,"width":1000,"height":400},
   "columns":["분기","매출(억원)"],"rows":[["1분기",120],["2분기",150]]},
  {"op":"chart_create","page":3,"type":"BAR_CHART_VER",
   "box":{"left":100,"top":200,"width":1000,"height":500},
   "categories":["1분기","2분기"],"series":[{"name":"매출(억원)","values":[120,150]}]}
]
```

기존 표 서식은 유지하되 요청한 칸 색만 바꾼다("표 칸 색 지정하기"). 새 표의 서식은 같은 페이지의 표 → 디자인 안에서
배경 밝기가 유사한 표 → 템플릿 본문 서체·팔레트 순으로 참조한다. 새 표의 글자 크기·열 폭·행 높이·숫자 정렬·패딩은
서버가 정하므로 장식을 덧그리거나 셀 텍스트를 수동 이동하지 않는다.
표의 폭은 `box.width`를 그대로 쓰고, 높이는 내용에 맞춰 `box.height`보다 작아질 수 있다. 큰 `box`로 빈 화면을 채우려 하지 않는다.
차트 값 라벨이 자동으로 숨겨져도 전체 수치를 보여야 하면 영역을 넓히거나 표를 함께 둔다.
공간 부족·입력 한계는 아래 절을, 최종 검토는 안내서 `design/plan-check`의 "plan만 검증하기"를 따른다.

## 표 영역 확보와 묶음 이동

공간은 **영역 조정 → 묶음 이동 → 같은 템플릿의 다른 페이지 선택 → 복제·분할** 순서로 확보한다.
표·차트 자리를 만들기 위한 일부 요소 삭제는 대안으로 사용하지 않는다. 삭제는 사용자가 요청했거나 콘텐츠 교체로
역할이 완전히 사라진 요소를 정리할 때만 기존 삭제 제약 안에서 허용한다. 겹침만으로 역할이 사라졌다고 판단하지 않는다.
차트 내부 라벨 문제는 안내서 `design/plan-check`의 "plan만 검증하기"를 따른다.

1. 데이터 양과 위 가독성 기준으로 `box`를 정하고 주변 여백을 확보한다. 빈 영역 안에서 위치·폭·높이를 조정하며,
   기존 장식에 맞추려고 글자나 패딩을 먼저 줄이지 않는다.
2. manifest·썸네일로 충돌 요소의 소속을 확인한다. 설명의 아이콘·원형 배경·연결선·제목·보조 라벨·본문을 한 세트로 본다.
   소속이 불명확하거나 이동하면 다른 충돌·캔버스 이탈·잘림이 예상되면 이동을 실행하지 않고 4번으로 간다.
3. 세트의 그룹 또는 노드를 빠짐없이 `move_nodes`에 명시하고, 그룹과 자식을 중복 지정하지 않는다.
   반복 세트는 전체에 같은 `dx`, `dy`를 적용하는 방법부터 검토하여 내부·세트 간 상대 위치를 보존한다.
   페이지 배경·공통 제목·머리말·꼬리말은 제외한다. 거리만으로 묶거나 일부 아이콘만 이동하지 않는다.
   이동 후 겹침·캔버스 이탈을 검증하고, 텍스트 폭을 바꿨으면 줄바꿈·잘림·가독성도 확인한다. 해결됐으면 여기서 멈춘다.
4. 이동이 부적절하거나 충돌이 남으면 같은 템플릿의 본문 페이지 가운데 기존 표·차트 또는 적합한 빈 영역이 있는 다른
   페이지를 선택한다. 템플릿에 표지, 목차, 간지, 마무리 같은 역할 페이지가 있으면 그 페이지는 빈자리가 넓어도 고르지 않는다.
   새 페이지에서도 데이터 양·가독성·주변 배치를 확인한다. 원래 페이지의 일부 요소를 지우는 방식으로 돌아가지 않는다.
5. 대체 페이지로도 담을 수 없을 때만 복제·데이터 분할을 검토한다. 복제하는 페이지도 본문 페이지다.
   표의 항목 이름 열과 차트의 카테고리·단위를 보존한다.
   사용자 지정 페이지는 안내서 `design/plan-structure`의 "콘텐츠와 페이지 구성하기"의 보존 기준을 따른다.

`table_overlap`은 작은 겹침도 알리는 기하적 검토 후보이며 `valid=true`여도 확인한다. `detail`의
`node`, `tableBox`, `nodeBox`, `intersection`을 manifest·썸네일과 대조해 배경 포함 관계와 셀·글자 가림을 구분한다.
경고만으로 삭제 대상을 정하지 않는다. 서버는 주변 노드를 자동 이동·삭제하지 않으며, 실제 충돌은 위 순서로 수정한다.

## 표 칸 색 지정하기

사용자가 칸·행·열·범주의 색이나 강조를 요청한 경우에만 바꾼다. 참고 표 이미지는 행·열과 내용을 맞춰 바뀐 칸 색만 옮긴다.

```json
{"op":"table_set_cell_style","page":3,"table":"3n5","cells":[[1,0],[2,0]],"fill":"#1F3F8F","text_color":"#FFFFFF"}
```

- 같은 색의 칸을 묶고 `fill`(배경)과 `text_color`(글자) 중 바꿀 값만 `#RRGGBB`로 지정한다. 나머지는 생략한다(`null` 금지). 색 미지정 시 manifest `palette`에서 고른다.
- `cells`는 칸 id 또는 최종 표 기준 0부터 세는 `[행, 열]`이다. 병합 칸은 첫 칸을 지정한다. 복제 페이지의 표와 칸은 `#2` 등 해당 식별자로 별도 지정한다.
- 새 표는 `table_create`에 `"cell_styles":[{"cells":[[1,0],[2,0]],"fill":"#1F3F8F"}]`를 넣는다. 좌표만 쓰며 0행은 `columns`다.
- 지정색은 `recolor` 후 적용된다. `text_color`를 생략하면 새 배경에서 읽기 어려운 글자색을 서버가 보정한다.
- 선·모서리·글꼴·병합 변경은 지원하지 않는다. 미지원 요청은 `notes`에 적고 편집 화면을 안내한다.

## 차트 작성 규칙

### 연산 선택

| 조건 | 행동 |
|---|---|
| `chart.editable: false` 또는 데이터와 표시 요소의 대응이 불명확함 | 다른 편집 가능 차트 또는 `chart_create` 사용 |
| 차트로 표현하기로 했고 사용할 차트가 템플릿에 없음 | `chart_create`로 데이터 기반 생성(위 절 참고) |
| 원고와 차트의 계열 수가 같음 | `chart_set_data` |
| 계열 수가 다름 | `chart_set_series`로 전체 카테고리·계열·값 지정 |
| 표현 목적과 현재 타입이 다름 | 아래 타입 선택 규칙에 따라 `chart_set_type` |
| 실제 수치가 없음 | 수치를 질문하거나 해당 차트·페이지 제외. 예시값·임의값·0으로 대체 금지 |

```json
{"op":"chart_set_series","page":3,"chart":"3n5",
 "categories":["1분기","2분기"],
 "series":[{"name":"국내 매출","values":[21.5,24.2]},
           {"name":"해외 매출","values":[8.1,12.4]}]}
```

- `categories`와 `series`는 비우지 않는다. 각 `values` 길이는 `categories` 길이와 같아야 한다.
- 카테고리·값은 문자열 또는 유한한 숫자, 계열 이름은 문자열을 쓴다.
- 차트당 데이터 연산은 둘 중 하나를 한 번만, 타입 연산도 한 번만 쓴다. 현재와 같은 타입은 지정하지 않는다.
- 타입만 바꾸면 예시 데이터가 남는다. 사용할 차트에는 데이터 연산도 넣는다.
- 계열은 배열 순서대로 스타일을 승계하고, 줄이면 뒤쪽부터 제거한다. 유지할 계열의 순서를 맞춘다.

### 타입 선택

사용자 지정이 없으면 목적에 맞는 현재 타입을 유지한다. 선택·변경이 필요하면 아래 표를 따른다.
겹침·잘림 대응은 안내서 `design/plan-check`의 "plan만 검증하기"를 따른다.

| 전달 목적 | 타입·조건 |
|---|---|
| 항목의 크기·차이 비교 | `BAR_CHART_VER`. 이름이 길거나 항목이 많으면 `BAR_CHART_HOR` 검토 |
| 변화 방향·연속성 | `LINE_CHART` 또는 `AREA_LINE_CHART`. 시간 데이터라는 이유만으로 변경하지 않음 |
| 전체 대비 비중 | `PIE_CHART` 또는 `DONUT_CHART`. 1계열·6카테고리 이하·상자 가로 ≤ 세로의 2배일 때 사용 |
| 막대와 선의 역할 구분 | `COMBO_CHART`, 최소 2계열. 새 차트는 마지막 계열만 선, 기존 콤보에 추가하는 계열은 선 |

타입 연산: `{"op":"chart_set_type","page":3,"chart":"3n5","type":"DONUT_CHART"}`.
파이·도넛의 카테고리를 늘려 새 조각 색이 부적절하면 다른 차트·표로 수치를 보존한다.

### 적용 순서

| 조건 | 순서 |
|---|---|
| 오버레이가 있고 타입·계열 수를 변경함 | 삭제가 허용되거나 새 콘텐츠와 맞지 않는 라벨이면 `delete_nodes` → 차트 연산. 그 외에는 다른 차트 사용 |
| 파이·도넛에 여러 계열 입력 / 콤보를 1계열로 축소 | 축이 있는 단일 타입으로 변경 → `chart_set_series` |
| 다계열 차트를 파이·도넛으로 변경 | 원고가 단일 계열일 때 `chart_set_series` → 타입 변경 |
| 단일 계열을 콤보로 변경 | `chart_set_series`로 계열 추가 → 타입 변경 |
| 위 조건에 해당하지 않는 타입·데이터 변경 | 타입 변경 → 데이터 연산 |
| 차트를 복제·복사함 | 원본 차트 연산 → `duplicate`·`copy_nodes`·`place_block` |

복제본 차트에는 별도 데이터를 지정할 수 없다. 계열을 분리할 때는 다른 원본 차트를 사용하거나 `chart_create`로 만든다.

### 외부 오버레이

- 유지할 라벨은 대응하는 카테고리·계열을 확인한 뒤 `replacements`로 수치를 맞춘다. 화면 위치나 슬롯 순서만으로 짝짓지 않는다.
  삭제한 라벨의 슬롯은 `replacements`에서 뺀다.
- 라벨만 받치는 원·배지임이 확인되면 라벨과 함께 `delete_nodes`에 명시한다. 공통 배경이거나 소속이 불명확한 도형은 삭제하지 않는다.
- `categoryCount: fixed` 또는 `overlayTexts`가 있으면 카테고리 수를 유지한다.
- `overlayBands`는 기존 수 이하로만 쓴다. 줄이면 서버가 오른쪽부터 삭제·재배치하므로 직접 삭제·가로 이동하지 않는다.
- 원본 계열 값과 일치하는 값 라벨의 세로 이동과 파이·도넛 라벨의 회전은 서버가 처리한다. `move_nodes`로 중복 이동하지 않는다.
- 자동 이동 대상이 아닌 라벨을 새 수치에 맞출 수 없으면 다른 편집 가능 차트나 `chart_create`를 사용한다.

### 라벨·축 옵션

`chart_set_data`·`chart_set_series`·`chart_create`의 연산 필드로 지정한다. 계열별 `series[].label_position`은 금지한다.

| 대상 | `label_position` |
|---|---|
| 선·면 | `"TOP"` 또는 `"BOTTOM"` |
| 비누적 세로 막대 | `"TOP"` 또는 `"INSIDE"` |
| 콤보 | `{"bar":"TOP","line":"BOTTOM"}`. 한쪽 생략 가능, 각 값은 위 규칙 적용 |
| 가로·누적 막대, 파이·도넛 | 지정 금지 |

- `label_position`을 지정하면 숨겨진 값 라벨도 켜진다.
- 비누적 세로 막대의 `"TOP"`은 양수 막대의 끝 위다. 음수 막대에서는 0축 위에 놓이므로 서버가 음수 점의 라벨만 막대 안으로 옮기고,
  값이 모두 음수면 Y축 최대값을 0으로 고정한다. 둘 다 `chart_readability`·`chart_axis_range` info로 알린다.
- 타입과 계열 수를 함께 바꿀 때 옵션은 중간·최종 타입 모두에서 유효해야 한다.
- `y_axis`는 선·면 차트에서 범위 의도가 있을 때만 지정한다. 예: `{"min":80,"max":120}`.
  유한한 숫자로 `min`·`max` 중 하나 이상을 지정하고 둘 다 있으면 `min < max`여야 한다.
- 막대·콤보·파이·도넛에는 `y_axis`를 쓰지 않는다. 옵션을 쓰려고 타입을 바꾸지 않는다.

### 자동 보정과 진단

계열 스타일·축 여백·글자 가독성 보정, 계열 수에 따른 범례 조절, 계열·카테고리를 식별할 수 없는 다계열·파이·도넛의 자체 범례 복구는 서버가 처리한다.
계열 색상 필드나 축·범례용 텍스트·도형을 만들지 않는다. 전체 색 변경은 `recolor`, 남길 외부 범례 이름은 `replacements`로 지정한다.

| 진단 | 행동 |
|---|---|
| `info` | 처리 내역이므로 같은 보정을 수동 연산으로 반복하지 않음 |
| `chart_readability`의 축소 배율이 0.5 | 축소 하한이므로 가독성 검토 |
| `chart_stale` / `chart_pruned` | 유지할 차트면 데이터 연산 추가. 쓰지 않으면 차트·페이지 제외 |
| `chart_zero_series` | 원고가 실제 0이면 유지. 원고에 없는 계열이면 제거 |
| `chart_scale` | 위 표현 선택 기준에 따라 차트 분리 또는 표 사용 |
| `chart_label_collision` | 안내서 `design/plan-check`의 "plan만 검증하기"의 시각 오류 대응 적용 |
| `chart_placement` | 새 차트 옆에 본문 폭의 빈 영역이 남거나 띠에 붙음. 본문 페이지면 `box`를 본문 열 폭과 간격에 맞추고, 표지·간지면 본문 페이지로 옮김 |

겹침 진단은 단일 Y축·비누적 선·면·콤보의 추정치이며 막대끼리는 검사하지 않는다.
경고 없음은 시각 검증 통과가 아니다. 최종 화면에서 표시한 값 라벨의 가독성과 카테고리 식별 가능 여부를 확인한다.
