# Aethon 사업계획 기술 작성 메모

기준: 2026-10-28. [발표용 기술 아키텍처](../../../docs/knowledge/presentation/ARCHITECTURE.md), [2026-10-27 개발·시험 기록](../../../docs/qa/codex-workflow-review-20261027/REPORT-ko.md), 관련 저장소 파일을 근거로 정리한 사업계획서 작성용 메모다. 이번 조사에서 외부 API를 호출하거나 제품 시험을 재실행하지 않았다. 아래 미래 구성은 선택 가능한 제안이며 일정·제품 완료나 클라우드 운영을 뜻하지 않는다.

## 1. 제품이 연결하려는 업무

초기 대상은 소규모 아이돌 기획사 및 지하·라이브·버추얼 아이돌의 뮤직비디오 제작을 맡은 조직이다. 제작팀이 음원·아티스트/IP 설정·참고 자료를 정리하고, 장면을 기획하고, 후보를 검토·선택해 편집·출력하는 작업을 하나의 작업대에서 잇는 방향이다. 대상의 실제 문제, 구매 결정과 반복 사용은 고객 인터뷰 및 시험 전 가설이다.

대화 모델은 **기획·맥락 이해 및 도구 사용 제안**, 영상 모델은 **장면 후보 생성**을 맡는 별개의 구성이다. 대화 응답이 영상 생성 성공을 뜻하지 않고, 대화 모델에서 영상 모델로 바로 실행되는 구조로 설명하지 않는다. 플랫폼에서 전송할 입력과 비용·권리·실행을 확인하고 승인한 뒤 생성 작업을 큐에 접수하는 방향으로 설계한다. 결과는 사람의 검토·선택을 거쳐 타임라인에 반영한다.

## 3. 개발 단계와 검증 게이트 제안

시점·비용·통과 목표값은 아직 확정하지 않는다. 각 단계의 판단 자료를 확보한 다음 범위를 늘린다.

1. **로컬 흐름 정리:** 음원·소재 입력부터 기획·Take 선택·검토·승인·편집·출력·재조회까지 하나의 작업을 운영자가 재현한다. 입력 권리 표시, 오류·저장·복구와 취소 후 상태를 점검한다. 합성 자료 시험과 실제 사용자 시험을 구분한다.
2. **제작 현장 검증:** 소규모 기획사·제작팀과 최근 제작 업무를 인터뷰하고 동의한 범위에서 관찰한다. 제작 의도·자료 전달·수정 이유·승인 주체·작업 시간 및 다음 곡에서 재사용할 정보가 실제로 무엇인지 기록한다. 현재 인터뷰·시험 고객·매출은 없다.
3. **실제 모델 연결을 별도로 검증:** 플랫폼 흐름이 준비되면 사용자가 허용한 계정·예산과 권리 범위 안에서 대화와 영상 모델을 각각 연결해 명시적 전송·승인, 요청/실패/복구, 품질과 과금 내역을 측정한다. 공급자 fixture 테스트만으로 실제 모델 성공을 주장하지 않는다.
4. **운영 확장 판단:** 사용성·권한·운영 인력·단위 비용을 확인한 뒤 다중 계정, AWS와 PostgreSQL 등을 단계적으로 검토한다. 고객 수·트래픽·계약 또는 특정 기술의 선행 도입 일정을 임의로 정하지 않는다.

품질 게이트는 결과물의 기술적 성공뿐 아니라 **권리·승인 → 영상 길이/재생·음원 싱크 → 화면·캐릭터 일관성 → 편집 가능성과 복구 → 담당자 승인 → 총비용 기록**을 포함한다. 정량 목표는 기준 영상과 평가자, 측정 방식을 정한 후 사용자와 확정한다. 사용자 만족도·작업시간 단축·절감률은 실측 전이다.

## 4. 향후 사용자·플랫폼·외부 서비스 구조

발표용 개념도는 [현재·향후 구조](../../../docs/knowledge/presentation/assets/architecture-overview-outlined.png), [AWS 비동기 상세](../../../docs/knowledge/presentation/assets/architecture-aws-detail-outlined.png)를 참조한다.

- **사용자 경계:** 브라우저 작업대에서 프로젝트와 권한을 관리하고 파일 제출·결과 확인·검토·승인한다. Next.js 화면은 기술 후보이며 적용을 확정하지 않았다.
- **Aethon 플랫폼:** 초기의 Python HTTP·SQLite·로컬 파일 구조에서 필요에 따라 FastAPI, ECS/Fargate, RDS PostgreSQL 등으로 이전하는 선택지를 검토한다. 개인정보·권한 분리, 계정 인증, 보관 기간과 비용 측정이 선행 과제다.
- **외부 AI:** 대화 AI는 기획과 도구 요청에, RunPod/Wan 또는 fal 등은 장면 생성에 각각 쓰는 후보로 분리한다. 사용자 승인 없이 외부로 소재를 전달하거나 제공자 API의 성공을 전제하지 않는다.
- **미디어와 비동기 처리:** S3 장면 저장 이벤트→SQS 알림→완료 조건 검증→PostgreSQL에 장면 상태 기록→FFmpeg 합성 워커→S3 최종본→CloudFront 전달을 예시로 검토한다. SQS는 알림이며 완료·품질 판정이나 파일 처리를 대신하지 않는다. 최종본 업로드 이벤트는 장면 알림에서 제외한다. DB 변경이 워커를 자동으로 실행하는 것처럼 단정하지 않는다.
- **운영 복원력:** 작업 ID 기반 중복 처리, 재시도·시간 초과, 장면 누락·중복 확인, 실패 큐와 재처리, 부분 결과 복구·비용 기록, 알림과 접근 통제를 설계·시험해야 한다. SQS와 RunPod 내장 큐를 동시에 도입한다면 각각의 책임·중복 처리 경계를 정의하며, Redis/Celery까지 기본 병행한다는 의미가 아니다.
- **분석 분리:** Databricks는 실시간 제작 요청의 필수 경로가 아닌, 권리와 사용 범위가 확인된 기록을 후속 수집·정제·분석하는 선택지다. 수집한 모든 사용자 영상을 학습에 자동 이용하지 않는다.

## 5. 데이터 생애주기와 책임

1. **수집 전 확인:** 사용자가 제출할 음원·인물/IP·참고 이미지의 권리, 외부 전송 대상과 목적을 표시하고 필요한 동의를 받는 방식을 설계한다. 권리 정보를 입력하는 기능이 법적 권리 보유 자체를 증명하지는 않는다.
2. **보관·기획:** 프로젝트·버전·샷·Take 및 권리·승인 기록을 사용자별 권한 범위에 연결한다. 로컬 SQLite/파일은 현재 경로이고 암호화·접근 제어·보관 기간·백업 및 삭제 정책은 향후 서비스 설계와 검증 과제다.
3. **생성과 기록:** 제공자별 모델·입력 버전·요청 ID·예산 승인·결과/실패·실제 청구를 연결한다. 이용자의 확인 후 외부 전송하고, 응답이 불명확할 때 중복 과금이나 중복 게시를 막는 복구 경계를 검증한다.
4. **검토·출력:** 결과 후보의 출처와 검토·선택·승인 상태를 남기고, 선택된 Take와 음원·자막을 조합해 최종 영상을 확인한다. 결과는 오류·권리 문제·사용자 요청에 따른 수정 또는 삭제 경로를 갖도록 설계한다.
5. **후속 분석·학습:** 수집 목적과 별도로 동의·계약 및 모델/데이터 라이선스를 확인한 기록만 분석한다. 사용자 원본의 학습 사용은 별도 권한·목적·범위를 확인하고, 접근·보존·철회 정책과 데이터 분리·감사를 설계한다.

## 6. 장기 모델 연구와 의사결정

[모델 고도화 도식](../../../docs/knowledge/presentation/assets/architecture-lifecycle-outlined.png)은 권리 확인된 데이터→대화·이미지·영상별 미세조정 또는 허용된 교사 기반 증류→기준 모델 대비 품질·비용·안전 평가→버전 등록·승인·추론 배포·관찰·롤백을 나타낸다. MLflow는 모델 기록·관리 후보이지 도입 사실이 아니다. 교사 모델의 가중치 또는 응답을 학습·증류에 쓸 수 있는지는 제공자별 약관과 계약을 확인해야 하며, 권리가 없으면 사용하지 않는다. 프롬프트·임베딩이나 공개 모델의 활용을 독자적인 기초 모델 완성으로 부르지 않는다. 연구 범위·데이터·GPU·인력·예산은 미확정이다.

## 7. 역할과 리스크

현재 대표 이성민 1인이 프로젝트를 추진하며, 본인이 제공한 현직 데이터 엔지니어 및 한화 포탈 데이터 엔지니어링 경험을 근거로 데이터·제품 개발을 설명한다. 영상 실무, UX, 고객 검증, 인프라·ML 운영의 보완은 **향후 협력·확보 검토**이며 확정 인력이나 채용 계획이 아니다.

| 위험 | 확인할 사항과 대응 방향 | 상태 |
|---|---|---|
| 수요·제품 적합성 | 기획사·제작자의 실제 업무, 납품 범위, 결제 주체와 지불 의향 인터뷰 | 미검증 |
| 영상 품질·일관성 | 실제 곡·IP의 허용된 자료로 후보의 연결성, 일관성·사람의 승인률 확인 | 실제 영상 모델 시험 전 |
| 비용·불확실성 | 생성·실패·재시도, 사람의 기획·편집·검토, 저장·전송·운영을 같은 기간의 승인본 수로 나누어 측정 | 원가·절감률 미측정 |
| 데이터·저작권·약관 | 입력·출력·교사 모델의 권리, 외부 전송 동의, 상용·학습 조건을 사용 전 확인 | 정책·실제 권리 확인 필요 |
| 운영·보안 | 계정/조직 격리, 비밀정보, 사고 대응, 중복 이벤트·복구·접근 이력을 서비스 환경에서 검증 | 현재 단일 로컬 작업 공간; 운영 미구현 |
| 기술·공급자 의존 | 모델별 품질·가격·장애와 변경 가능성을 비교하고, 대체·전환 및 자체 모델 연구의 경제성 평가 | 후보·가설 |
| 1인 실행 역량 | 제품 핵심 흐름과 고객 접점을 우선하고 필요 시 영상·UX·운영 역할을 보완 | 협력·채용 미확정 |

공급자 공개 단가에 따른 예시와 외주 견적은 [v7 비용 근거](../../aethon-ir-v7-pipeline/research/cost-evidence.md)에 따르며, 생성 API 소계와 완성작 총비용 또는 외주 전체 견적을 동일 범위로 취급하지 않는다.
