# Aethon 발표자료 온톨로지

피벗 이후에도 **Aethon**이라는 이름을 유지하는 현재 프로젝트의 발표자료를 만들 때, 발표 목적과 청중부터 메시지, 슬라이드, 주장, 근거, 시각화, 검토까지 연결해 사용하는 지식 구조입니다. 범용 슬라이드 구성은 선택 가능한 초안이며, 실제 2026년 경진대회 v7의 목적·시간·최종 파일은 [현재 IR 자료 모음](CURRENT-IR.md)을 따릅니다. 범용 온톨로지의 안정 ID 번호와 실제 PPT 페이지 번호는 다릅니다.

발표에 사용하기 전 [온톨로지 운영 안내](../ONTOLOGY-OPERATIONS.md)에 따라 관계와 사업 수치를 검증하고, 작성 문맥 및 변경 영향을 확인합니다.

## 파일과 범위

- [현재 IR 자료 모음](CURRENT-IR.md): 대표 정보, 시장 4단계, 조사·비용 근거, 최종 PPT·PDF·노트와 검수 결과를 연결합니다.
- [아키텍처와 그림 원본](ARCHITECTURE.md): 현재·향후 구조, 모델 고도화, AWS 비동기 상세도와 SVG·PNG를 보존합니다.
- [대표자 정보](../business-plan/FOUNDER-PROFILE.md) / [TAM·SAM·SOM·LAM](../business-plan/MARKET-SCOPE.md): 2026-10-28 대표 확인을 반영한 공통 기준입니다.

- [ontology.json](ontology.json): 개념·관계 정의와 Aethon에 적용한 데이터, 초안 슬라이드 순서, 제작·검토 흐름. `id`는 각 항목을 참조할 때 사용하는 안정 식별자입니다.
- [슬라이드 작성 브리프](SLIDE-BRIEF-TEMPLATE.md): 투자자·지원사업·고객별 적용, 장표 구성, 조사 수치의 조건과 산출물 추적표를 포함한 작성 템플릿입니다.
- [사업계획 온톨로지](../business-plan/ontology.json): 발표에 사용할 사업 근거와 가설. 발표 온톨로지의 `external_references`가 해당 ID를 명시합니다. 서로 파일을 참조할 뿐, 기존 `project_kit` CLI나 제품의 런타임 온톨로지에 자동 등록되거나 동기화되지는 않습니다.
- JSON의 로컬 출처 `path`는 **저장소 루트 기준**이며, `locator`는 출처 안의 해당 부분입니다. 대화에서 확인한 사용자 설명은 파일이 아니라 대화 출처로 표시합니다.

## 사용하는 순서

1. 발표 목적, 청중, 발표 시간, 언어, 사용처와 원하는 산출물 형식을 확인합니다. 미확인 값은 채워 넣지 않습니다.
2. `deck_outline`의 후보를 목적과 청중에 맞게 선택·수정합니다. 각 슬라이드에서 전달할 메시지와 연결된 주장, 근거, 도표의 적합성을 확인합니다.
3. 주장에 연결된 출처 원문과 시점·검증 범위를 확인합니다. 사업 가설을 검증된 사실로 바꾸거나, 격리 시험을 실사용자 성과로 표현하지 않습니다. 과거 Aethon의 고객·매출·가격·제휴 등을 자동으로 승계하지 않습니다.
4. 확인되지 않은 수치나 시장·고객 성과가 필요한 슬라이드는 보류하거나 `미확인`으로 표시하고, 필요한 자료와 검증 담당자를 정합니다. 숫자 차트는 수치·단위·기간·출처가 확인된 경우에만 만듭니다.
5. 실제 발표자료를 작성할 때 슬라이드별 사용한 ID와 출처 버전, 작성일, 검토 상태를 함께 기록합니다. 변경된 상위 근거의 영향 슬라이드를 재검토하고 필요하면 PPT를 다시 생성합니다.

## 상태 해석

`documented_decision`은 문서나 사용자 대화에 기록된 방향이며 기능 완성의 증거가 아닙니다. `reported_test`는 기재된 시험 범위에 한정된 보고입니다. `reported_external`은 외부 기관이나 공급자가 보고한 수치로 자사 실적이 아닙니다. `hypothesis`는 확인할 가설, `unknown`은 확인되지 않은 항목입니다. `proposed`는 발표용 구성 제안으로 채택이나 완성을 뜻하지 않습니다. 발표자료의 전체 설계와 출처 확인은 사람이 수행해야 합니다.
