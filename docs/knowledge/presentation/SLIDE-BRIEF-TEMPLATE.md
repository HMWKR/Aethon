# Aethon 발표자료 작성 브리프와 슬라이드 설계

**2026-10-28 현재 발표본:** [CURRENT-IR](CURRENT-IR.md)의 v7과 [대표자 정보](../business-plan/FOUNDER-PROFILE.md), [시장 범위](../business-plan/MARKET-SCOPE.md), [아키텍처](ARCHITECTURE.md)를 우선한다. 아래 표는 다른 발표에도 재사용할 수 있는 템플릿이며, 현재 대회는 한국어 발표 8분·질의 7분으로 확인했다. 피벗 설명은 대표의 최신 요청대로 본문에 강제하지 않는다.

이 문서는 실제 PPT를 만들기 위한 작업 템플릿이다. [발표 온톨로지](ontology.json)와 [사업계획 온톨로지](../business-plan/ontology.json)의 안정 ID를 사용한다. 실제 청중과 공고·요청 조건을 확인한 뒤 필요한 슬라이드를 선택하며, 현재 순서·제안은 확정안이 아니다. 제품의 피벗 배경과 검증 결과의 기준은 제품 정체성 및 작업 보고서의 최신 상태로 다시 확인한다.

## 시작 전 입력

| 항목 | 작성값 |
|---|---|
| 발표 유형·청중·의사결정 | 미확인: 투자자 / 지원사업 심사자 / 잠재 고객 / 기타 |
| 발표 언어·시간·슬라이드 수·파일 형식 | 미확인: 공고 또는 요청 조건 확인 |
| 청중이 취할 행동과 요청사항 | 미확인: 투자·지원·도입·협업 등 구체 금액과 조건 |
| 공개 범위·권리 | 미확인: 코드·제품 화면·음원·인물·상표·고객 정보 사용 가능 여부 |
| 피벗 이후 법인·팀·자금·고객·매출 | 대표 1인 진행 및 고객 인터뷰·시험 고객·매출 없음은 본인 확인. 법인·자금·권리·투입 시간은 미확인 |
| 제품 현황 | 보고서의 날짜와 시험 범위를 확인하고 시연 가능 기능과 계획을 구분 |
| 기준일·작성자·검토자 | 작성 시 기입; 출처 열람일과 별개 |

## 청중에 따른 구성 조정

| 대상 | 강조할 판단 | 추가로 확인할 입력 | 우선 장표 |
|---|---|---|---|
| 투자자 | 문제의 크기와 초기 고객, 반복 구매 가설, 성장 경로와 검증 단계 | 실제 고객·매출·유지율·자금 계획, 조달 조건 | 1–2, 4–8, 10–12 |
| 정부 지원사업 | 공고 적합성, 수행 역량, 산출물·일정·예산, 정량 성과지표의 측정 방법 | 해당 공고·평가 기준, 신청 자격, 협약 기간·지원비목·증빙 | 공고 순서에 맞춰 1–4, 7, 9–12 |
| 고객·협력사 | 현재 가능한 작업과 사용 흐름, 결과물 예시, 사용 조건·다음 행동 | 상대의 제작 방식·권리·예산·도입 범위, 실제 제품 기능 | 1–3, 5–7, 9, 12 |

위 목록은 예시다. 공고가 있으면 공식 양식·페이지 제한과 필수 항목이 우선이다. 투자자용 매출 전망이나 고객용 제안 가격은 실제 입력 전 확정하지 않는다.

## 장표 설계

각 장표의 한계는 작은 글씨의 면책 문장으로 숨기지 않고 핵심 수치 옆 또는 발표자 노트에 표시한다. `[확인]`은 기록된 출처의 범위, `[가설]`은 검증이 필요한 주장, `[미확인]`은 정보 공백을 의미한다.

| 번호·온톨로지 ID | 전달할 내용과 필수 입력 | 활용 근거·상태 | 추천 표현 및 검토 |
|---|---|---|---|
| 1. 소개·피벗 `PPT-SLIDE-001` | 현재 Aethon이 누구의 어떤 제작을 돕는지; 기존 프로젝트에서 현재 방향으로의 변화 | `[확인]` `BP-FACT-001`, `BP-FACT-002`; 과거 고객·성과 승계 `[미확인]` | 피벗 전·후 간단한 흐름. 대표가 확인하지 않은 이전 사업의 실적을 쓰지 않는다. |
