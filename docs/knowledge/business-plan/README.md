# Aethon 사업계획 온톨로지

이 디렉터리는 피벗 후에도 Aethon이라는 이름을 유지하는 IP 음악영상 제작 프로젝트의 **사업계획서 작성용 지식 구조**다. [ontology.json](ontology.json)은 개념·주장·가정·미확인 항목·관계·출처와 계획서의 각 장을 안정 ID로 연결한다. 완성된 사업계획서나 제품의 실행 코드가 아니다.

실제 검토용 본문은 [Aethon 상세 사업계획서](BUSINESS-PLAN.md)에 있다. 2026-10-28 기준 16개 장과 출처, 현재·향후·모델 고도화 구조도 3종을 포함한다. 사업 방향, 현재 확인 상태, 가설, 제안과 미산정 재무 입력을 구분했으며 제출 기관의 지정 서식에 맞춘 최종 제출본은 아니다.

2026 창업아이디어 경진대회 서류용 HWP 8칸의 현재 기준본은 [HWP 8칸 제출 본문](HWP8-SUBMISSION.md)이다. 10월 16일 본의 서술 구조에 현재 사업 내용(2026-10-28 타깃 개정 `BP-FACT-014`까지)을 적용했고, [전문가 의견 반영 기록](REVIEW-FEEDBACK-20261016.md)에 적힌 10월 16일 의견 01~03의 보완 사항을 반영했다. 단, 같은 날 후속 결정(`BP-FACT-015/016/017`)과 3차 검증 R3-1·R3-2·R3-7은 아직 HWP 원고에 반영하지 않았다(마지막 단계에서 반영). 원고는 상세 사업계획서와 같은 기준 문서·온톨로지 ID를 사용하지만, 이 후속 결정은 기준 문서를 먼저 확정한 뒤 마지막 단계에서 원고에 반영하므로 그 전까지는 원고 일부가 기준 문서와 다르다. 기준이 바뀌면 md 기준 문서(상세 계획서·시장 범위·조사·온톨로지)를 먼저 확정하고 HWP 8칸 원고는 마지막에 반영한다. 기준 문서를 남기는 것이 우선 목적이며 HWP 원고는 대표가 직접 고칠 수 있으므로, 반영 전 HWP 원고가 기준 문서와 다르면 기준 문서를 따른다.

실제 작성은 [사업계획 작성 가이드](WRITING-GUIDE.md)와 [시장 조사](RESEARCH-20261027.md), [비교 대상 가격 조사](COMPETITIVE-PRICES-20261027.md)를 참고한다. 조사 수치는 2026-10-27 확인한(일부 절은 2026-10-28 추가) 외부 지표이며, 시장 전체 수치를 Aethon의 매출이나 접근 가능한 시장으로 간주하지 않는다.

개념·관계 규칙과 자동 검증·근거 조회·변경 영향 확인은 [온톨로지 계약](../ONTOLOGY-SCHEMA.md)과 [운영 안내](../ONTOLOGY-OPERATIONS.md)를 따른다.

2026-10-28 최신 대표·경력·자격·1인 팀은 [대표자 정보](FOUNDER-PROFILE.md), 초기 고객과 TAM·SAM·SOM·LAM은 [시장 범위](MARKET-SCOPE.md)를 기준으로 한다(같은 날 타깃 개정: AI·음악영상 스튜디오와 기획사 콘텐츠팀, 소프트웨어 지출 단위 금액 산정. 근거는 [타깃·경쟁·권리·시장 조사](RESEARCH-20261028.md)). 같은 날 후속 결정으로 웹툰·서브컬처 IP 스튜디오를 더해 1단계 표적을 세 집단으로 넓히고 기획사와 IP 권리자를 검수·승인 주체로 두었으며(`BP-FACT-015`, SAM-c 웹툰 제작 및 제공 사업체 추가), AI 생성 표시 관련 서술을 대표 결정으로 폐기했고(`BP-FACT-016`, 사유 미기재, 13주 기능 추가의 예외는 최소 결제 연결만), 성장 3단계를 ‘기술 고도화와 글로벌 진출’로 바꾸고 첫 해외 시장을 일본으로 정했다(`BP-FACT-017`). 같은 날 검토한 외부 보고서(PDF)는 다수 수치가 미확인이거나 근거가 없어 원고 근거로 직접 쓰지 않는다(`BP-SRC-036`). [현재 IR 자료 모음](../presentation/CURRENT-IR.md)에서 아키텍처 그림 원본, 조사 근거, 최종 PPT와 발표자 노트를 함께 확인한다. 현재 팀·타깃이 미확인인 과거 기록보다 이 최신 확인을 우선하되, 시장 금액·가격·원가·법적 주체는 별도 미확인으로 유지한다.

## 사용 방법

1. 작성 목적, 독자, 제출 요건과 기준일을 정한다. `plan_sections`의 순서는 조정할 수 있다.
2. 해당 장의 `inputs` ID를 `concepts`에서 찾고, 연결된 `sources`의 해당 절을 읽는다. 경로는 저장소 루트 기준이며 대화 출처에는 파일이 없다.
3. `classification`과 `verification`을 지키고 `limit`의 제한을 함께 반영한다. 설계 결정·문서에 적힌 가설·제한된 제품 시험·실제 고객 성과는 서로 다르다.
4. 미확인 항목은 확인 전까지 빈칸이나 확인 필요로 둔다. 시장 규모, 고객 수, 가격, 투자금, 재무 수치를 만들어 내지 않는다. 외부 자료와 가격은 실제 작성 시 원출처와 날짜를 다시 확인한다.
5. PPT는 이 파일의 `BP-…` ID를 참조해 같은 주장과 한계를 사용한다. 도구의 `validate`는 사업·발표 수치 스냅샷을 비교하고, `impact`는 영향 후보를 찾는다. 출처나 주장 변경 시 장과 실제 PPT는 사람이 다시 검토하고 갱신한다.

## 구조와 관계

`sources`는 근거의 위치, `concepts`는 하나의 의미를 가진 지식 항목, `relations`는 출발 항목과 대상 항목의 관계다. `supported_by`는 주장에서 출처로, `tests`는 실험 설계에서 검증 대상 가설로, `depends_on`은 소비하는 주장이나 계획에서 근거로 향한다. `plan_sections.inputs`는 장에서 참조하는 개념이다. ID는 다른 문서가 재사용할 수 있도록 유지하며, 의미가 크게 바뀌면 새 ID를 만든다.

분류는 `decision`(현재 방향), `evidence`(기록된 한정적 관찰), `hypothesis`(검증할 주장), `unknown`(확인이 필요한 정보), `experiment`(검증 계획)이다. `verification`은 근거 범위를 나타내며 승인이나 사업성의 보증이 아니다. 최초 기록은 초안이므로 원본 문서가 업데이트되면 재검토해야 한다.

## 기존 지식과의 경계

최신 제품 정체성 보충문은 과거 사업 문서의 명칭 충돌에 우선한다. 이전 Aethon에서 방향을 전환하고 이름을 유지한다는 것은 이전 고객·매출·자산·권리·가격·성과의 자동 승계를 뜻하지 않는다. 별도 AethonSaaS 프로젝트와도 구분한다. 과거 사업 문서의 고객군·가치 제안은 가설로만 활용한다.

기존 `docs/knowledge/project_kit`의 레지스트리, `kb.py`와는 별도 JSON이다. 이 파일은 해당 CLI에 자동 등록되거나 검증되지 않으며 런타임 제품 온톨로지에도 자동 반영되지 않는다. 실제 사업계획서나 슬라이드 작성 전 원본과 현재 상태를 확인한다.
